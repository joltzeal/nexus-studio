# Vinted 美国分类目录清洗与使用规范

日期：2026-11-14。本地清洗已完成，运行时读取和上架接入待实施。
本地目录用于页面未自动分类时的兜底，不覆盖上传图片后页面已有的有效分类。

## 1. 数据来源与产物

用户下载的 `catalogs.json` 是本轮源数据。
来源接口为美国站 `GET /api/v2/item_upload/catalogs`，本次按用户要求以本地快照为准。
未登录直接访问曾返回 403；不因此要求用户开启在线目录服务。
源文件保持原样，没有覆盖或删除；清洗数据位于：

```text
plugins/sales-agent/resources/vinted/us-catalogs.json
```

这份文件将作为插件自带资源接入，不要求最终用户准备 `catalogs.json`。
本轮尚未修改插件打包脚本，不能声称当前发行插件已经包含或使用它。

## 2. 字段保留与删除

保留原始树结构，不同时保存另一份扁平目录。
运行时可以由树生成 ID 索引、父节点映射和完整路径；顺序沿用源文件，不重新排序。

| 原字段                    | 处理                     | 原因                                            |
| ------------------------- | ------------------------ | ----------------------------------------------- |
| `id`                      | 必须保留                 | 平台分类身份；不能按名称重新生成                |
| `title`                   | 必须保留                 | 搜索、展示与模型候选                            |
| `full_title`              | 原来存在就保留           | 区分相同名称的不同上下文                        |
| `catalogs`                | 仅非空数组保留           | 保存父子关系；省略时表示末级节点                |
| `restricted_to_status_id` | 非 null 时保留           | 可能影响适用状态，不能丢失限制                  |
| `path`                    | 校验与祖先路径一致后删除 | 可完整重建；本次 2,908 个非空值均与祖先路径一致 |
| `photo`                   | 删除                     | 分类图标和缩略图与上架字段无关                  |
| `badge`                   | 删除                     | 本次全部为 null；不参与分类或上架               |
| 顶层 `code`               | 验证为 0 后删除          | 网络响应状态不属于目录数据                      |

本次全部 2,916 个 `restricted_to_status_id` 均为 null，所以产物中没有该字段。
若未来来源出现未知字段，清洗器拒绝处理，要求维护者明确决定是否保留，
避免静默删除新增的业务限制。
叶节点只表示目录结构末端，不能据此断言该账号一定有发布权限。

## 3. 产物格式

外层保存固定范围、原始文件摘要和内容版本：

```ts
// 数据契约说明，不是已接入运行时的 TypeScript 导出。
type LocalVintedCatalog = {
  schemaVersion: 1
  platform: 'vinted'
  market: 'US'
  locale: 'en-US'
  source: {
    endpoint: '/api/v2/item_upload/catalogs'
    sha256: string
  }
  revision: string
  catalogs: CatalogNode[]
}

type CatalogNode = {
  id: number
  title: string
  full_title?: string
  restricted_to_status_id?: number
  catalogs?: CatalogNode[]
}
```

`revision` 是对 `JSON.stringify(catalogs)` 的 UTF-8 字节计算的 SHA-256，
不包含生成时间、绝对机器路径或账号信息。
`source.sha256` 对原文件原始字节计算；源文件仅调整格式会改变来源摘要，
分类内容不变时内容版本保持一致。
生成文件使用单行紧凑 JSON，并在 `.prettierignore` 中明确排除，避免格式化重新撑大文件。

## 4. 重新清洗

从仓库根目录执行：

```bash
rtk proxy node scripts/clean-vinted-catalogs.mjs catalogs.json plugins/sales-agent/resources/vinted/us-catalogs.json
```

使用仓库固定的 Node 24.18.0。命令不访问网络，不构建主程序或插件，
拒绝将输入和输出指向同一文件。
它在内存中完成结构验证，写入临时文件后原子替换输出；
失败时保留已有产物，不留下半份有效目录。

验证包括成功响应、正整数且唯一的 ID、非空名称、子数组、
原路径与祖先关系一致，以及已知字段和限制字段类型。
清洗有 16 MiB 输入预算、100,000 节点和 64 层上限，
超过时明确报错，不截断数据。

本次清洗器的 12 项回归先观察到缺少实现的失败，再实现并通过。
覆盖结构和 ID 保留、同名分类、不丢非空限制、拒绝源文件覆盖、
错误输入保留旧输出和重复运行的字节一致性。
另已对原始快照与产物进行独立逐节点对照：2,916 个 ID、顺序、父子关系、
名称、`full_title` 和限制值全部一致；2,908 个非空祖先路径全部可重建，
原文件摘要、分类内容版本与产物摘要均匹配。

## 5. Jev 与上架怎样使用

应用启动后只读取插件自带的规范文件，不从 API 自动刷新。
解析后建立内存索引，不把整个目录塞进任务检查点或每一次模型请求。

需要预备兜底时，在浏览器执行前逐层发送当前子分类及祖先上下文。
这份目录每个分支最多 20 个子分类，普通路径最多 5 层；
不需要为了容纳完整 2,916 个节点新增向量数据库。
可以把互相独立的候选路径判断放入同一次 Jev 请求，
依赖上一层选择的下一层判断仍需等待上一层结果。

Jev 的候选键使用临时枚举映射到真实 ID；真实 ID 从本地映射取回，
不让模型编造分类编号或完整路径。
保留少量候选分支、明确的无匹配结果和人工选择入口；
具体门槛由项目商品评估确定。

同一商品修订、目录版本、站点、模型配置和规则版本可复用分类结果。
手动选择优先于本地模型推荐，执行前确认它仍属于本次冻结的兜底目录。
美国目录不能直接用于其他国家站点；在没有对应站点数据时明确不支持自动分类。

上传图片后先等待页面推荐并读回实际分类。
有有效页面值就使用该值，即使其 ID 不在本地快照中，也不以本地目录覆盖。
只有页面最终为空时才应用预先准备的本地候选；没有候选时暂停补齐，
不在窗口执行期间再调用 Jev。
兜底的目录 ID、路径及 revision 与页面实际使用的分类分别记录，
不能将网页自动推荐伪标为本地目录选择。

本地快照没有分类属性定义。品牌、颜色、尺码、材质、成色、包裹尺寸
和平台验证要求必须单独从已验证的页面规则取得。
目录不包含这些字段不代表它们在发布时不需要。

## 6. 维护与发行边界

更新目录须重新清洗、审查差异并测试。
删除、改名、移动或新增分类都通过 ID、祖先路径和内容版本比较；
不以“通常不变”为由忽略冲突。
新插件需要将文件复制到发行目录、写入包摘要并实际验证包内读取，运行时不能依赖仓库路径。

已运行任务保留原快照；目录更新不能悄悄改变既有商品分类。
若页面没有自动分类，且真实表单不接受冻结的兜底，暂停该商品并提示维护，
不改用在线回退目录或相近类目。
页面接受的新分类仅作为该次操作的官方页面证据，不据此自动修改整份本地文件。
新格式只支持 `schemaVersion: 1`，不添加兼容原始 API 大对象的运行时读取分支。
