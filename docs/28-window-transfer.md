# 窗口加密迁移

## 目标与边界

窗口导出与设备同步共用窗口快照。快照包含选中的窗口配置、固定内核版本、
指纹种子、分组、持久浏览器数据和插件提供的关联账号、代理。
本机数据库继续明文存储；导出文件必须设置密码并加密，不保存密码。

采用整份快照和显式导入。直接复制浏览器目录不能解决跨设备 Cookie 解密，
因此同时通过浏览器 API 读取 Cookie、localStorage、IndexedDB、OPFS，再在目标机器恢复。
不引入中心业务服务器，不合并两台电脑运行中的数据库。

## 使用入口

桌面应用的窗口管理页支持选择已关闭的窗口，再使用工具栏中的导出或设备同步。
导出设置至少 8 个字符的密码，并用系统文件选择器保存 `.nexuswindow` 文件。
导入先选择文件、输入密码并解密预览，再选择独立副本或明确覆盖同标识窗口。
密码只用于本次操作，不写入数据库。

设备同步需要两端安装「窗口同步」插件。发送端选择窗口后生成一次性配对码，
接收端粘贴配对码并接收，传输完成后再明确导入。必要时可选择其他可直达的主机地址。
普通浏览器预览不能执行本机文件选择、迁移或设备同步，不返回模拟成功。

## 实现顺序

1. 核对默认 GeoIP 设置和代理启动等待链路，修复更新地址与代理传递。
2. 实现版本化快照、流式认证加密、路径校验与本地导入事务。
3. 通过插件迁移接口携带所选窗口的账号与代理，导入失败回滚新增数据。
4. 实现设备直连同步插件，提供配对码、进度、取消和完整性校验。
5. 接入窗口选择、导入导出与同步对话框，补充模块文档和实际检查记录。

## 一致性

导出要求先关闭窗口，迁移期间宿主阻止对同一窗口启动、编辑和删除。
快照时使用绑定内核读取站点状态，并在读取完成后关闭临时浏览器。
不复制进程锁、缓存、临时文件、符号链接或可执行浏览器内核。
未设置指纹种子的旧窗口需要明确提示其环境存在随机性；新窗口保存固定种子。

浏览器目录复制仅在 `user-data` 根目录排除 `Last Browser` 与 `RunningChromeVersion`：
前者是本机浏览器路径记录，后者是 Chromium macOS app shim 的运行版本链接。
跳过时不读取或跟随链接，不复制目标，也不删除源文件；这两个名称出现在子目录时
不适用新增排除规则。未知符号链接、目录链接和特殊文件仍使导出失败。
Cookies（包括 `Default/Network/Cookies`）、localStorage、IndexedDB、OPFS 的
`File System` 目录及 Service Worker 的 CacheStorage 保留，原有缓存排除规则不扩展。
导入仍先完整校验归档路径和条目类型；即使归档内链接使用上述名称，也必须拒绝，
不能因本机导出忽略运行痕迹而放宽导入。

上游依据为 Chromium 的
[app shim 生命周期实现](https://github.com/chromium/chromium/blob/145.0.7632.109/chrome/browser/apps/app_shim/app_shim_listener.mm)
和 [Last Browser 路径记录实现](https://github.com/chromium/chromium/blob/145.0.7632.109/chrome/browser/web_applications/chrome_pwa_launcher/last_browser_file_util.cc)。
临时配置目录实测中，CloakBrowser `151.0.7922.108.3-pro` 启动退出码为 77 后留下
`RunningChromeVersion` 和已有排除规则覆盖的 `Singleton*` 链接；
将同类残留链接放入 Rust 回归用例可复现「浏览器数据中包含不可迁移的链接或特殊文件」。
干净关闭的 CloakBrowser `145.0.7632.109.2` 未留下这些链接；
本次未实测到 `Last Browser` 符号链接，也未读取用户原始失败目录，因此不将它认定为
用户此次失败的确切条目。上述实测只使用临时 profile、缓存与无账号环境，结束后清理。

导入使用原精确内核版本对应的本机二进制；缺失时获取同版本，
不可用则失败，不能静默改用新版本。导入副本拥有独立本机目录。
覆盖只允许显式选择并关闭对应窗口；覆盖失败恢复原资料。
快照分别保存 `kernelVersion` 和 `kernelKind`，从适配器的本机清单按窗口绑定路径取得，
不把 Chrome `--version` 的显示值当成完整包标识。例如 `145.0.7632.109.2`
可能仅显示为 `145.0.7632.109`；`.2` 与 `.3` 不能互换，基础包与新版包也不能互换。
缺失包准备完成后重新读取清单，核对完整版本、类型和实际二进制路径。
命中缓存时也离线探测目标二进制的 `--version`，与快照的窗口绑定显示版本严格比较；
刚准备的内核使用准备步骤已探测的显示版本，避免把完整包修订号误存成显示版本。
显示版本不一致时，在插件写入和目录替换前停止导入。
覆盖还需确认本机已有窗口的包标识一致；无法识别原包时停止操作，不推测版本。
启动在读取配置和调用代理插件之前持有窗口操作锁，避免代理解析期间被迁移替换环境。
跨操作系统时恢复可移植站点状态并提示操作系统指纹差异，不承诺完全相同。
平台可主动撤销会话，成功恢复 Cookie 不等于平台保证继续登录。

导入预览与实际导入都通过运行时的 `validate-state` 命令复用完整站点数据解析器，
在内核获取、插件写入和目录替换之前完成校验。该命令不启动浏览器或请求网络，
不能仅凭 `schemaVersion` 和一个空对象就认定快照可恢复。
正常启动时先恢复站点数据，成功后才报告浏览器可用；恢复失败保留待恢复文件。

## 文件与加密

文件扩展名为 `.nexuswindow`。版本化容器使用 PBKDF2-HMAC-SHA256
（600000 次、随机盐）派生 AES-256-GCM 密钥，数据压缩后分块认证加密。
每块使用唯一 nonce，并认证容器头、块序号与结束标记。
错误密码、篡改、截断、追加内容与格式不符必须失败。
解包设置文件数、大小和路径限制，拒绝绝对路径、父级跳转、硬链接与符号链接。
解压总读取量（包括 tar 元数据与结束后的 gzip 输出）也有独立上限，
每条 GNU/PAX 扩展元数据在进入 tar 解析前限制为 64 KiB。
压缩载荷上限为 20 GiB；密文文件额外包含 49 字节容器头、每帧 4 字节长度和
16 字节认证标签，以及必需的空结束帧。密文大小校验计入这些开销，
不会拒绝由本程序正常导出的边界文件。
临时目录仅供本次操作，操作结束清理；加密包不包含应用激活码和无关插件密钥。

原始目录副本不包含浏览器可执行文件，接收端按原精确版本使用本机内核。
迁移仅针对所选窗口；不带走整个工作区、应用更新配置、插件商店凭据或无关账号。

## 插件迁移接口

`transfer.export` 接收 `windowIds` 与 `endpointIds`，返回插件自有、版本化的数据。
代理能力额外接收 `includeDefault`，仅在所选窗口使用默认代理时携带该端点。
宿主不解释业务字段，只转交插件；代理插件另外返回默认端点标识。
`transfer.import` 接收 `data` 与 `windowIdMap`，返回导入收据及代理端点映射。
失败调用 `transfer.rollback`，全部成功调用 `transfer.commit`。
宿主只接受具有相应能力的已安装插件，并阻断 WebView 通用调用这些内部方法。
接收设备缺少需要的插件或迁移方法时明确失败，不丢弃关联后报告成功。

## 中断与恢复

导入通过临时目录、原目录备份、SQLite 事务和落盘收据协调提交。
失败时先恢复原生窗口资料，再补偿插件写入；原生恢复完成必须先写入检查点，
后续重试插件补偿不能重新覆盖用户后来编辑的窗口。
如果原生恢复或检查点写入失败，相关标识会一直暂停启动、编辑、删除和再次导入，
直到应用重启并成功完成持久化恢复。

应用启动先完成所有待恢复的原生事务，再加载窗口绑定。
插件收据不阻塞启动；窗口管理页独立检查收据状态并显示未完成的恢复提示，
安装或更新所需插件后刷新可重试。已经提交的导入仅重试插件收据清理，
已经回滚的导入仅重试插件补偿，不重新替换本机浏览器数据。
这套恢复针对进程中断和可检测的文件写入失败，不作为整机断电原子性的证明。

## 设备同步

同步插件传输已加密的相同快照。配对码含一次性高熵秘密，
双方通过挑战应答验证对端，传输后校验完整大小和 SHA-256。
同一局域网或地址可达的两台设备可以直接传输；自动 NAT 穿透和中继未接入。
同步为手动快照，不持续合并运行中的 Cookie；双方各自保有可独立打开的副本。
同步首次导入保留窗口标识，以便后续双向更新；本机已有该标识时默认拒绝，
必须明确选择覆盖并关闭对应窗口。普通文件导入的“副本”会生成新标识。
两端都修改后，后一次覆盖以确认的完整快照为准。
