# 插件返回与关联操作确认

## 页面返回

主程序 `0.1.31` 在顶栏提供返回按钮。按钮的可访问名称和悬停说明包含目标页面，
例如“返回 Vinted 账号池”。账号池的执行记录、商品历史和详情跳转继续使用统一详情导航；
返回只切换页面，不重新提交目标任务。

侧栏继续按已安装并启用的插件目录生成。访问过的页面在当前应用会话内保留，
包括搜索、筛选、页码、表单状态和页面自身的滚动容器。页面使用 React Activity 隐藏，
隐藏期间清理页面效果和轮询，返回时恢复效果并按原条件读取数据。
全局短信等待、原生任务与插件后台调度保持各自的生命周期。

未访问的页面不提前挂载。返回历史最多保留 50 项，点击当前页不会追加重复历史。
停用或卸载插件时移除其缓存页面及返回目标；插件目录读取失败只标记读取错误，
不会将原目录当作已卸载。重新安装插件不会自动恢复之前清除的页面。
商品编辑器在页面暂时隐藏时保留未保存表单和已上传图片，重新显示不会用远端
旧记录覆盖草稿；明确取消时清理未使用图片。后台操作的结果会在返回页面后
呈现，避免隐藏时清理效果导致按钮永久停留在“处理中”或再次发起同一写入。

详情跳转持有独立的意图编号。启动时收到批次深链而目录尚未返回时，先等待目录，
再打开对应插件；返回、侧栏切换或成功确认目标插件已移除时取消尚未消费的意图。
后续直接进入插件不会套用已放弃的账号或商品筛选；旧意图的清理不会覆盖更新的跳转。
显式打开另一条业务记录时切换到请求的记录，来源列表的筛选保持不变。

这些状态保存在内存中，不承诺跨应用重启恢复。业务记录继续来自插件或原生持久化，
不会为了页面返回把账号密码、邮件正文、浏览器凭据或模型密钥写入 localStorage。
目标插件重启、版本变化及业务数据实际增删仍可能触发其已有页面刷新或安全重置。

## 关联操作

账号关联的解除、替换与删除必须先展示明确的确认弹窗，说明操作对象和影响。
确认前不发送写请求，取消保留原关系。执行时阻止重复提交，失败保留确认框和错误，
成功后再刷新账号资料。具体覆盖入口见[账号池](24-vinted-accounts-plugin.md)。
窗口页的快捷手机号解绑、账号更换与解除关联同样先确认，并在写入前核对
当前窗口关系、账号联系方式及受影响窗口；过期资料必须刷新后重新确认。
邮箱与账号池相互发起的邮箱替换、解绑也在保存前确认。

解除账号与手机号或邮箱的关联是修改本地业务关系，不代表删除 SIM8 号码、
微软邮箱或关闭浏览器。确认文案必须区分这些操作，不展示无关的高风险能力。

## 验证边界

导航状态单测覆盖跨插件返回、重复导航、卸载清理和目录失败。
受控浏览器交互测试验证筛选、页码、滚动、隐藏效果清理和弹层可见性。
邮箱的远端已读写入及账号确认交互分别在模块测试中验证；
测试结果与真实邮箱、原生应用安装验证的区别见[质量记录](09-quality-and-testing.md)。
