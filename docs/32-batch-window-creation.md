# 批量创建窗口

## 使用入口

窗口管理工具栏新增「批量创建」。每批支持 1–100 个窗口，可填写名称前缀，
按 `前缀-01`、`前缀-02` 生成名称；留空时逐个随机命名。新名称会避开当前已有窗口
及本批次中的同名记录，最长 40 个字符。

Vinted 账号池支持单选、多选和全选当前筛选结果。搜索不会清除其他筛选条件下的已选项，
工具栏始终显示总选择数，可用「清空选择」重置。刷新后移除已经删除的账号选择。
选中账号后点击「批量创建窗口」，每个账号对应创建一个窗口并关联该账号：

- 数量固定为所选账号数，每批最多 100 个，不会静默截断超量选择。
- 名称前缀留空时使用账号名；长名称截断，同名加编号。填写前缀时使用统一编号。
- 平台固定为 Vinted，保留已有账号记录及其密码、手机号和接码链接。
- 账号已有窗口关联时，表单标记「已有关联」，需要勾选确认才会新增窗口关联。
  不解除原有关联，也不复制一个新账号。

这些入口调用真实 `profile_create`。浏览器预览不能创建本机窗口。
创建和关联不会自动启动浏览器或执行账号登录。
开始前必须保存激活码；没有类型、历史版本选择或免激活创建路径。

## 统一配置与独立环境

单个窗口、编辑窗口及批量创建共用 `window-editor.tsx`，保留以下配置：

| 配置                              | 批量行为                                 |
| --------------------------------- | ---------------------------------------- |
| 浏览器内核                        | 后台解析最新稳定内核，创建后绑定实际版本 |
| 平台、备注、分组                  | 应用到所有窗口；账号池入口固定 Vinted    |
| 直连 / 手动 HTTP、SOCKS5 / 代理池 | 应用到所有窗口，不根据创建结果回退直连   |
| 代理 IP 自动匹配                  | 默认开启，沿用现有在线 IP 查询配置       |
| 时区、语言、尺寸、起始地址        | 应用到所有窗口                           |
| 指纹种子                          | 每个窗口单独随机生成，创建后固定         |

选择代理池的具体代理时，所有窗口保存同一个插件 ID 和代理条目 ID。
选择「使用当前默认代理」时，提交前读取一次默认条目并固定其 ID，
不会在逐个创建过程中跟随默认项变更。手动代理沿用既有输入校验，
代理检测仍是用户主动操作，不增加创建前必须通过网络检测的条件。

开始前读取当前窗口清单，为每个条目生成独立的正整数种子，
避开清单及本批次已经使用的种子。发生随机碰撞时寻找下一个可用值。
整批的名称、种子、账号映射和公共配置在开始时固定；重试不重新随机。
每个成功窗口仍由原生核心生成自己的 UUID 和独立数据目录，
种子与配置写入原有 SQLite 记录，继续受原生不可变绑定规则保护。

## 执行、失败与恢复

前端按条目串行调用既有创建命令，避免同时触发多次内核准备。
创建成功后，如有账号，再调用 `vinted.accounts.bind`；
主程序不向 Rust 核心增加 Vinted 账号字段或专用业务命令。

结果表逐行展示窗口名、账号、种子、当前状态及实际失败原因。
创建期间禁止重复提交及通过 Esc、遮罩或关闭按钮丢弃任务。
「完成当前项后停止」会等待当前创建和账号关联结束，再停止后续条目；
随后可以继续，已经完成的条目不再执行。

- 创建失败：保留其他成功项，重试只处理未完成条目。
- 创建响应失败：用计划中的名称和种子核对原生列表；能找到已保存窗口时复用它。
  无法读取列表时保留未确认状态，重试前必须先核对，不能直接再次创建。
- 窗口已创建、账号关联失败：保留窗口 ID，显示「待关联」；
  重试仅调用账号关联，不创建第二个窗口。
- 执行中出现新的重复关联：显示待确认条目；用户勾选后，只对对应账号使用
  `confirmDuplicates: true`，其他账号不隐式确认。
- 页面列表刷新失败：独立展示刷新错误，不改变已完成的创建及关联结果。
- 窗口管理列表按创建时间倒序展示，同一秒的批量结果按后创建优先排列。
  账号池在成功后刷新关联数量，并取消成功账号的勾选，失败项保留选择。

批量任务进度保存在当前弹窗中，不是跨应用重启的持久任务队列。
关闭弹窗或退出应用后，不会自动继续剩余条目；已经成功创建的窗口及账号关联仍由
各自存储持久保存。存在「待关联」项时可先在结果表重试，
关闭弹窗后也可从窗口管理手动关联。整批不是一个跨核心与插件的原子事务。

## 实现与验证

- `apps/desktop/src/features/spaces/window-batch.ts`：计划、名称和种子去重、
  单任务防重、逐项创建与关联、重试核对及停止控制。
- `apps/desktop/src/features/spaces/window-editor.tsx`：共用完整配置表单，
  批量数量、前缀及只读随机种子展示。
- `apps/desktop/src/features/spaces/batch-window-dialog.tsx`：配置读取、
  账号重复确认、进度、错误及结果刷新。
- `apps/desktop/src/features/spaces/spaces-page.tsx`：窗口页入口及结果合入。
- `apps/desktop/src/features/accounts/accounts-page.tsx`：账号多选及一对一创建入口。
- `apps/desktop/src/features/spaces/window-batch.test.ts`：部分失败、重复调用、
  种子碰撞、配置快照、关联重试、结果核对及停止恢复。

不新增 Rust 命令、数据库 schema 或插件 RPC 方法。
账号池插件沿用现有 `list` / `bind` 协议，此次入口由主应用提供。
实际执行的检查与未覆盖的原生运行边界见[质量与验证](09-quality-and-testing.md)。
