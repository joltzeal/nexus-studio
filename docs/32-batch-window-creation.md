# 批量创建窗口

## 使用入口与连接

窗口管理工具栏提供「批量创建」。每批支持 1–100 个窗口，可填写名称前缀，
按 `前缀-01`、`前缀-02` 生成名称；留空时逐个随机命名。
名称避开目标连接已有窗口及本批次中的同名记录，最长 40 个字符。

窗口页按当前浏览器连接创建；账号池入口需要选择一个已启用、已确认范围且具备
`create` 能力的连接。API 探测成功不等于账户身份已经核验，
外部连接须先在设置中人工确认当前厂商账户或工作区。
整批开始时固定连接和能力，不在执行过程中切换 Provider 或账户。
AdsPower 编辑与插件代理在验证前不可用，不能通过批量入口绕过，
具体能力与限制见[浏览器接入](05-browser-integration.md)。

Vinted 账号池支持单选、多选和「全选当前页账号」。表头复选框只修改当前页的选择，
翻页、搜索、筛选、重置筛选和切换每页条数均保留其他页及筛选条件下的已选项。
工具栏始终显示全部选择数，可用「清空选择」重置。刷新后移除已经删除的账号选择。
账号池每页默认 20 条，可切换 20 / 50 / 100 条；批量创建使用全部已选账号，
页码与当前筛选不改变目标集合。每个账号创建一个窗口并关联：

- 数量固定为所选账号数，每批最多 100 个，不会静默截断超量选择。
- 名称前缀留空时使用账号名；长名称截断，同名加编号。填写前缀时使用统一编号。
- 平台固定为 Vinted，保留已有账号及其密码、手机号和接码链接。
- 账号已有窗口关联时需勾选确认才会新增关联；不解除原关联、不复制新账号。

入口调用统一 `browser_window_create({ input })`，每项带独立且稳定的
`operationId`、选定的 `connectionId` 和配置。浏览器预览不能执行原生创建。
创建和关联不自动启动浏览器或执行账号登录，插件关联统一使用 Raccoon UUID，
不能改用 AdsPower 或比特浏览器的环境 ID。

## 公共配置与 Provider 差异

单个、编辑及批量窗口共用 `window-editor.tsx`，实际字段受 Provider 能力控制：

| 配置                                 | 内置 CloakBrowser                    | 外部 Provider                                |
| ------------------------------------ | ------------------------------------ | -------------------------------------------- |
| 内核                                 | 最新稳定包或已安装完整包，创建后固定 | 厂商管理，创建请求 `kernelVersion: null`     |
| 指纹种子                             | 每窗口独立生成正整数，创建后固定     | 厂商管理，`settings.fingerprintSeed: null`   |
| 平台、备注、Raccoon 分组             | 公共配置应用到所有条目               | 同为业务元数据，不用厂商环境 ID 替换分组关系 |
| 代理模式                             | 直连、手动 HTTP/SOCKS5、代理插件     | 按实际能力提供；接管环境可保留厂商代理模式   |
| 出口匹配、语言、时区、尺寸、起始地址 | 按内置运行时映射                     | 按厂商适配能力校验，不套用内置 Node 配置     |
| 激活码与缓存                         | 必须配置内置激活码                   | 不要求 CloakBrowser 授权或缓存               |

选择代理池具体项时，所有窗口保存同一插件 ID 和整数端点 ID。
选择「使用当前默认代理」时，开始前读取并固定该端点，逐项执行不跟随默认项变化。
手动代理按当前校验处理；代理检测仍是用户主动操作。
代理配置、解析或鉴权失败不能改为直连；不支持某种模式时须明确拒绝。

内置批次开始前读取目标窗口清单，为每项生成种子，避开已有和本批种子；
随机碰撞时寻找下一个可用值。外部批次不生成或传递 Raccoon 数字种子。
名称、操作 ID、账号映射和公共配置在开始时固定，重试不重新随机。

## 内置批次的精确内核

内置创建前必须保存激活码。内核清单通过 `kernel_status` 独立加载，
失败或刷新不清空当前选择，也不阻止已配置激活码的用户请求最新稳定版。
所需版本不在清单中时，可先到「应用设置 → 浏览器内核」下载完整包后刷新。
编辑已有窗口不展示选择器，不改变原绑定。

显式完整包版本在每次创建、继续和重试时保持不变，不能失败后改成最新包。
默认最新的批次先提交 `kernelVersion: null`；首个确认成功或协调恢复的内置窗口
返回完整包版本后，后续条目固定使用该版本。
该固定先于账号关联，即使关联失败也保留；暂停继续也不重置。
完整包来自 `WindowRecord` v2 的 `kernel_version`，不能用 Chrome 显示版本补修订号，
也不保留旧响应缺字段兼容。外部批次不执行这一内核固定流程。
每项首次提交时冻结完整请求，已提交项的 `kernelVersion`（包括当时的 `null`）
在重试时保持原值；批内版本固定只影响尚未提交的后续项，不回改已有请求。

每个窗口由统一服务分配 Raccoon UUID，记录通过 `WindowStore` 写入 SQLite。
只有内置窗口获得独立受管 `user-data` 目录；外部环境由厂商创建并保存，
Raccoon 仅保存不可变绑定、能力相关配置与操作结果。

## 执行、失败与恢复

前端逐项串行创建。后端先以 `operationId` 保存请求和阶段，再调用 Provider，
同一操作 ID 不允许变更请求。每项保留首次提交的完整 payload 和操作 UUID，
用户手动重试时将两者原样再次交给幂等 `browser_window_create`，
由后端持有操作锁并判断下一步：

| 后端已有阶段              | 同一操作 ID 和请求再次到达时的处理                       |
| ------------------------- | -------------------------------------------------------- |
| `failed`（明确失败）      | 复用原窗口 UUID 和原草稿执行允许的重试，不分配第二套身份 |
| `submitted` / `uncertain` | 只按操作标记和读取结果协调，不重复发送原始厂商创建写入   |
| `committed`               | 返回已保存的窗口，不重新创建                             |

待处理操作列表有意排除 `failed` 和 `committed`。
前端不再查询该列表的阶段来决定是否允许重试，也不能因列表没有某项就推定尚未提交；
请求能否执行或必须协调由后端按持久记录裁决。
创建成功后，如有关联账号，再调用 `vinted.accounts.bind`；
不向 Rust 窗口记录增加 Vinted 私有字段。

结果表按项显示窗口、账号、适用时的种子、状态及失败原因。
执行期间禁止重复提交和通过 Esc、遮罩或关闭按钮丢弃任务。
「完成当前项后停止」等待当前创建和绑定结束再停止后续项，之后可继续未完成项。

- 创建失败后的手动重试：保留其他成功项，原样重送该项冻结的 payload 和操作 UUID
  到幂等创建入口，不先用待处理列表推断是否安全。
- 响应丢失或结果不明：当前尝试可立即调用一次
  `browser_operation_reconcile({ operationId })`；仍未确认则保留待核对状态，
  不用名称加种子猜测成功。之后手动重试仍走同一幂等创建入口，
  不生成新操作 UUID，也不重复发送结果不明的原始厂商写入。
- 窗口已创建但账号绑定失败：保存 Raccoon 窗口 ID 并显示待关联，重试仅绑定账号。
- 出现新的重复关联：逐项确认，仅对应账号使用 `confirmDuplicates: true`。
- 连接未确认或观察失败：保留条目及操作身份，先恢复并确认连接范围，不能换账户继续原操作。
- 列表刷新失败：独立显示错误，不改写已完成的创建和绑定结果。

窗口列表使用持久 `sortOrder` 等统一排序字段，批内结果不会依赖同秒时间戳猜测顺序。
成功后账号池刷新关联数并取消成功账号的勾选，失败项保留选择。
插件关联查询使用全局 Raccoon 窗口集合；切换浏览器 Tab、连接不可用或环境缺失
不自动解除其他窗口与账号的关系。

弹窗中的整批进度不是跨应用重启的自动任务队列；关闭后不会自动执行剩余条目。
已经创建的窗口、账号关联和后端操作记录分别持久化，结果不明项仍可从待处理操作入口协调。
待关联项可在结果页重试，关闭弹窗后也可手动关联。
整批不是跨核心、厂商和插件的原子事务，不能因后续项失败删除前面的成功窗口。

## 实现与验证边界

- `window-batch.ts`：连接和配置快照、名称/种子计划、冻结请求与稳定操作 ID、
  串行幂等创建、响应丢失后的单次协调与绑定重试。
- `window-editor.tsx` / `window-kernel-field.tsx`：按能力提供配置与内置精确版本选择。
- `batch-window-dialog.tsx`：连接选择、重复关联确认、进度、错误和结果刷新。
- `spaces-page.tsx` / `accounts-page.tsx`：窗口页与账号池入口、选择与结果合入。
- `window-batch.test.ts` 等同目录用例：配置快照、种子碰撞、操作不明、关联重试、停止继续及内核固定。

批量复用通用创建与操作协调接口，不新增专用批量 Rust 命令。
当前统一记录为 v2，既有 SQLite 只在启动初始化时升级一次；
旧命令、运行时记录和导入格式不提供兼容读取。
本次文档更新未执行构建、Rust、真实厂商 API、真实浏览器或 Windows 测试。
实际检查与未覆盖范围统一见[质量与验证](09-quality-and-testing.md)。
