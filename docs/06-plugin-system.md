# 插件页面与长期插件系统

插件开发者的具体 manifest、能力接口、目标宿主协议与验收要求见
[插件对接开发规范](14-plugin-integration-guide.md)。本文侧重产品现状与长期边界。

## 当前插件页面

插件中心是八个主页面之一。页面分两组：宿主发现到的插件包，以及未接入的能力占位。
插件包读取真实 manifest，按状态提供安装、启用、停用、重启、卸载与清单查看；
授权弹窗展示能力、网络域名、密钥槽与存储范围；密码由插件保存在私有目录，页面不回显。
状态只有“可安装、已安装未启用、运行中、进程失败”四种，全部来自宿主检查。
“演示占位”保留平台账号、接码和环境配置三个入口，状态为“待接入”，没有执行入口；
图片能力已由 `studio.ai-image` 接入，不再是占位。
卡片不使用彩色装饰或插画，优先呈现清楚的能力范围与状态。
非桌面环境下只展示随仓库提供的 manifest 声明，并标注“仅桌面应用”，不显示安装或启用按钮。
成功反馈只描述真实结果：安装完成不等于插件运行中，启用失败会显示真实错误。
完整页面交互见[演示页面](11-demo-pages.md)，宿主行为见[插件宿主](17-plugin-host.md)。

## 当前工程基础

`packages/plugin-sdk` 保留 manifest、能力与权限声明契约。
Rust `core::plugin_host` 在其上实现发现、安装、登记表、受管进程与权限检查点。
`core::plugins` 的内存登记表保留为调度器侧的代理端口抽象，不再代表插件系统的全部能力。
插件以独立 Node.js 子进程运行，标准输出只承载逐行 JSON 协议。
manifest 在安装时严格校验，能力在启用时授权，调用前逐项检查。
密码由插件明文保存在自己的私有目录，宿主不读取；`secretRef` 只在插件内部使用。
当前不加载第三方来源的插件，不提供市场下载与自动更新。

`plugins/proxy-pool` 是一个已实现的代理插件包：它按第 7 节协议提供 RPC 服务端，
具备私有存储、密钥引用、检测与订阅能力，可在桌面应用中安装、启用，并作为窗口的代理来源，
见[代理池插件](15-proxy-plugin.md)。

`plugins/address-generator` 是第二个已实现的插件包：`address.generator` 能力提供公开地址查询、
地图选点资料与用户名生成，见[地址生成器插件](19-address-generator-plugin.md)。
它的密钥槽只保存页面加载 Google Maps 用的浏览器 Key，生成结果不落盘。

`plugins/shared-supply` 是第三个已实现的插件包：`supply.catalog` 能力提供分类商户、商品搜索、
以图搜图与本地收藏，见[共享货源插件](21-shared-supply-plugin.md)。
它不需要任何密钥槽，收藏写在插件私有目录。

仓库内存在插件实现不等于插件系统已经通用可用：只有 `proxy.provider`、`address.generator`
与 `supply.catalog` 具备真实调用路径。

## 长期首阶段信任模型

当前真实插件只考虑受信任 TypeScript 代码，通过独立 Node.js 进程承载。
维护者控制代码来源、版本与依赖，并保留可追溯记录。
独立进程有助于生命周期与故障管理，本身不能证明恶意代码被限制。
manifest 和 permissions 是描述与授权契约，不是操作系统沙箱。
没有额外措施时，Node.js 代码可能访问进程用户可访问的文件与网络。
不得向用户承诺未经实现的文件、网络或系统隔离保障。
当前不开放任意第三方插件执行。

## 后续 SDK 与 manifest 契约

SDK 仅暴露稳定能力，不透出 SQLite 连接、Rust 内部结构或引擎对象。
请求需明确输入、结果、错误、取消与超时语义。
协议版本与兼容范围应可校验，不兼容时拒绝执行。
manifest 应表达插件标识、版本、入口、兼容范围与所需能力。
具体字段以实际 contracts 和 SDK 为准，文档不另建平行 schema。
声明必须对应宿主检查点，没有执行检查的字段不能称为强制权限。
manifest 不嵌入账号凭据、访问令牌或代理密码。
启用记录持久化不等于 manifest 已验证或权限已落实。

## 宿主生命周期

宿主区分发现、验证、启动、可调用、停止与失败状态，页面状态由这些检查派生。
进程初始化成功不代表浏览器、账号或业务任务已经可用。
崩溃、超时与启动失败返回明确错误，并结束未完成调用。
停止先尝试协作退出，再按受控策略结束进程与回收资源。
取消必须有确定最终状态，取消后不能继续反馈执行成功。
重复请求是否可重试随实际能力定义，不默认所有调用幂等。
插件退出不得破坏其他页面或工作空间的数据。

## 数据与浏览器边界

插件通过宿主提供的私有目录持久化，不直接持有授权 SQLite 写入权。
插件不能枚举或读取 CloakBrowser 授权记录。
密码是插件私有目录里的明文文件，不经过宿主，也不做加密或隔离；
调用入口的授权检查不等于网络或文件隔离。
浏览器调用遵守不可变启动快照、profile 独占锁和必需代理失败阻断。
插件不能通过自己的路径绕过代理或抢占 profile。
会话与标签页的资源限制分别定义，不共用未经验证的配额解释。
详细规则见[浏览器接入](05-browser-integration.md)与[本地数据](07-data-storage.md)。

## 第三方开放与验证

开放前需落实隔离方式、来源验证、文件与网络访问边界及更新完整性。
应明确哪些限制来自宿主协议，哪些来自操作系统或执行环境。
若继续采用受信任进程，产品说明必须准确表达这一信任范围。
当前测试覆盖宿主安装、授权、拒绝、调用、卸载与启动阻断，以及演示状态、持久化与 SDK 契约行为。
真实代理链路、真实浏览器启动与 Windows 行为尚未验证。
插件和运行时的授权与打包约束见[分发](08-distribution.md)。
[质量矩阵](09-quality-and-testing.md)由主线填写，不将页面状态测试视为插件安全验证。
