# 商品管理插件

## 用途与入口

`studio.products` 提供独立商品库，能力为 `product.catalog`。
安装并运行后，侧栏通过宿主目录自动显示“商品管理”。
商品页面随主程序交付，插件包只提供资料、图片与 RPC 服务。
插件版本为 `1.0.0`，最低核心版本为 `0.1.29`；已经发行的 `0.1.28` 不支持此新能力。
`1.0.0` 已发布至 R2；配套 `0.1.29` 已生成本地 macOS Apple Silicon 安装包，
实际证据和其他平台边界见[质量记录](09-quality-and-testing.md)。

商品库是ecom agent 的商品来源。AI 生图负责生成素材，商品管理负责维护
可编辑的商品资料；生成记录本身不作为 Agent 的商品身份。
ecom agent 已接入真实商品库读取、任务快照与分配持久化；平台执行与验收边界见
[执行规范](44-sales-agent-architecture.md)。
[独立交互原型](42-sales-agent-demo.md)已经提供基于商品库语义的左右分配面板，
其中商品与窗口均为内存示例，不修改本插件的资料。

## 使用流程

### 手动创建与编辑

商品页支持创建、编辑、确认删除、搜索、准备状态、发布状态与来源筛选，
以及每页 20 / 50 件的后端分页。
每件商品保存名称、英文标题与描述、SKU、价格、币种、分类、成色、品牌、尺寸、标签和备注。
分类始终选填，价格支持 USD、GBP、EUR。

商品有三个准备状态：

| 状态   | 要求与含义                                               |
| ------ | -------------------------------------------------------- |
| 草稿   | 名称必填，其他上架资料可后续补充                         |
| 待上架 | 需要标题、描述、正数价格、成色及至少一张图片；不要求分类 |
| 已归档 | 保留商品及图片，退出日常待上架准备流程                   |

“待上架”只表示资料完整，不代表已经发布到电商平台。
手工商品允许编辑英文文案；商品库不会暗中调用模型翻译、补全商品事实或修改价格。
商品的发布事实另外保存，不挤入这三个准备状态；本轮没有库存数量或订单业务。

每件商品最多 12 张图片，支持 PNG、JPEG、WebP，单张最多 8 MiB。
编辑器支持添加、移除、设为主图和调整顺序，第一张为主图。
保存失败保留当前表单；编辑以修订号检查并发修改，不覆盖更新后的商品。

### CSV / JSON 导入

商品页“导入资料”支持选取本地文件或粘贴文本，并提供 CSV / JSON 空模板。
CSV 需要表头，JSON 为商品对象数组。
单次上限为 512 KiB，逐行返回新增、跳过和错误，保留行号。
跳过数量包含校验失败行，错误列表提供其中失败行的原因。

导入字段与模板一致：

```text
name,title,description,sku,price,currency,category,condition,brand,size,tags,note,status
```

文件导入仅处理商品文字资料，不读取图片路径或自动下载网络图片。
可以先导入草稿，再在编辑器中添加本地图片。
`ready` 行同样受图片完整性要求约束，不能用文件导入绕过待上架校验。
同一文件内容的同一行按来源去重，已有商品的手工修改保持原样；
改写文件内容属于新的来源，不使用 SKU 合并不同商品。

### 从 AI 生图导入

有两个入口：商品页“从 AI 生图导入”，以及 AI 生图记录详情中的“导入商品库”。
后者在当前页面完成，不跳转到其他插件。

1. 从可用的生成记录选择批次，尚在生成或识图中的记录不可导入。
2. 一条生成记录导入为一件商品，复制该记录中的整组已完成图片。
3. 使用成功的成片识图文案；没有时使用记录已有的标题与描述，保留原商品来源。
4. 商品以草稿创建，不猜测价格、成色、品牌或尺寸。
5. 在商品库中补齐资料，确认图片及顺序后改为待上架。

含失败视角的记录可以导入已有成片；未生成的视角不伪造为图片。
某张已登记成片缺失、数据损坏或图片数量超限时，整件商品导入失败。
同一生成记录再次导入会返回已有商品，不覆盖后续编辑。
插件在导入期间重启或更新会停止本次操作，用户可重新发起。
取消或失败时清理本次未使用的图片；成功提交后取消不能撤销已保存商品。

### 发布状态与使用窗口

商品表格单独展示“未发布／已发布”和最近一次发布的窗口名称、发布次数。
点击“查看历史”分页读取发布记录，可查看全部使用窗口，包括名称快照与 Nexus UUID、
平台、刊登 ID 和链接、发布时间、记录时间与发布所用商品修订号。
历史区域限制高度并内部滚动，支持每页 20 / 50 条，读取失败可以重试；
普通编辑器展示发布摘要并可进入只读历史。
平台商品链接使用应用现有的默认浏览器打开端口。

“已发布”只根据持久化的发布事实得出，不由待上架状态、窗口分配或原型模拟结果推断。
它表示历史成功发布，不保证平台商品当前仍在线。当前没有自动刊登、撤架或远端状态同步。
用户不能通过普通编辑表单伪造发布，CSV/JSON 与生图导入也不能带入发布历史。
ecom agent 仅在平台结果核对后登记发布记录；分配和任务创建不会产生刊登记录。

后续受信任执行器确认平台成功后调用：

```ts
products.publications.record({
  productId, // Nexus 商品 UUID
  operationId, // 稳定发布操作 UUID
  windowId, // Nexus 窗口 UUID
  windowName, // 发布时的名称快照
  platform,
  listingId,
  listingUrl, // HTTP(S)
  productRevision, // 实际执行快照的修订号
  publishedAt, // ISO UTC 时间
})
// => { product, alreadyRecorded }
```

服务端补充发布记录 UUID 与 `recordedAt`。此方法记录调用方确认的事实，
不访问平台、不验证远端刊登是否存在，也不作为独立的发布能力。
字段通过严格 schema 校验；未来宿主需要控制哪个执行器可以写入，见
[Agent 架构方案](44-sales-agent-architecture.md)。

同一操作、同一内容的重试幂等，不增加历史或修订号；
同一操作变更内容或跨商品复用会拒绝。不同操作重复使用同一
`(platform, windowId, listingId)` 也会拒绝，删除商品后的收据仍保留。
第一次记录发布时，历史、收据与修订号递增原子提交，失败不会反馈成功。
商品已编辑时，允许记录不高于当前修订号的旧执行快照，不允许未来修订。
正常编辑、导入去重和刷新不会清除发布历史。

完整商品详情和写入回执只含发布次数与最新一条发布记录，不携带完整历史；
历史通过 `products.publications.list` 按页读取，避免提交成功后因回执过大而无法确认。
商品列表另外省略未显示的品牌、成色、尺寸、标签及来源详情，保留来源类型，
这些资料仍保存在商品详情中，也继续参与后端搜索。
最新记录按发布时间比较，时间完全相同时以记录 UUID 确定稳定顺序。
摘要与历史使用同一个公开排序函数，保留 ISO 时间中的亚毫秒精度。
发布状态筛选在后端执行，窗口名称、窗口 UUID、刊登 ID 与平台可通过商品搜索查询。

历史分页契约：

```ts
products.publications.list({ productId, page: 1, pageSize: 20 })
// => { productId, productName, productRevision, items, total, page, pageSize }
```

`pageSize` 支持 20 或 50；页码超过末页时回到实际末页。
`items` 只含当前页，`total` 是该商品的全部发布次数。
商品详情、保存与发布回执中的 `publicationCount` 和 `latestPublication`
为发布摘要，不能把缺少全量历史数组理解成“未发布”。

## 数据与身份

Rust 仍是 SQLite 唯一所有者；本插件不创建 SQLite 连接。
商品与图片索引明文保存在宿主提供的私有目录 `products.json`，
图片字节独立保存在 `images/<UUID>.bin`。
文件是插件私有业务存储，不是加密文件，也不写 Keychain 或 localStorage。

每件商品拥有稳定 UUID、递增修订号和创建序号。列表按创建序号倒序，
编辑商品不改变创建顺序。同名商品与相同 SKU 的不同商品可以分别保存，
SKU 不作为商品身份或去重条件。
来源分别为手动创建、文件导入和 AI 生成记录；原监控商品的公开来源另行保留。
这些标识均不等于平台刊登 ID 或浏览器窗口 ID。

图片必须先写入商品插件，再提交资料中的引用；提交资料采用临时文件与原子替换。
持久化失败不修改内存中的已保存资料，也不反馈成功。
坏文件不会被当作空商品库覆盖。读取图片会核对文件大小、类型和 SHA-256。

AI 导入通过两端各自的公开 RPC 分块复制字节，不读取另一个插件的目录。
因此删除原生图历史不会删除已导入商品的图片。
新建请求标识、导入来源记录和修订检查分别处理重复创建、重复导入与旧版本编辑。
删除商品后保留请求收据，避免延迟到达的旧创建请求重新创建已删除记录。

## RPC 与扩展

公开契约：`@nexus/plugin-products/contracts`。
运行时导出指向编译后的 JavaScript，Vitest 的源码别名只用于无构建检查。

| 方法                                       | 用途                                   |
| ------------------------------------------ | -------------------------------------- |
| `products.list`                            | 按关键字、状态、来源查询一页摘要       |
| `products.get`                             | 获取商品资料、有序图片元数据与发布摘要 |
| `products.save`                            | 带创建请求标识的新建，或带修订号的编辑 |
| `products.publications.record`             | 幂等记录已确认发布及使用窗口           |
| `products.publications.list`               | 按页读取商品的只读发布历史             |
| `products.remove`                          | 带修订号的删除                         |
| `products.import`                          | CSV / JSON 资料导入及逐行结果          |
| `products.sources.find`                    | 通过生图记录 ID 查询已有商品           |
| `products.importAi`                        | 提交已复制图片的生图商品，按来源幂等   |
| `products.upload.begin/chunk/finish/abort` | 受限会话上传图片                       |
| `products.images.read`                     | 分块读取插件自有图片                   |
| `products.images.discard`                  | 清理未被任何商品引用的图片             |

图片分块最大 192 KiB，Base64 与 JSON 均须处于宿主协议行上限内。
上传按顺序校验分块索引、实际字节数和图片签名；最多同时存在四个上传会话，
会话过期、终止或插件停止时释放未完成内容。
完成上传时持久化上传 ID 与图片 ID 的对应记录，响应丢失后可重复完成或终止并清理；
商品提交时消耗清理记录，后续终止旧上传不能删除商品正在引用的图片。
读取端校验进度和总长度，不允许无进度循环、错误大小或不完整内容产生可用预览。
所有方法使用 `product.catalog`，不申请浏览器、网络或凭据能力。
它不提供配置导入导出方法：商品和图片属于业务数据，不能混入应用配置备份。

Agent 通过稳定商品 ID 获取完整资料和有序图片，并在任务开始时固定执行快照。
发布结果使用独立发布记录，不能用商品的准备状态冒充平台成功。
[窗口分配原型](42-sales-agent-demo.md)已提供左右固定高度、拖拽与区域内滚动，
支持大量窗口，仍只操作独立的内存示例。

- 插件：`plugins/products`，包括存储、资料导入、图片会话及行协议。

- 生图入口：`apps/desktop/src/features/ai-image/detail-dialog.tsx`。

- 发行工作流已纳入插件构建、检查、打包及握手校验选择；本轮不运行发行。

实际执行的检查见[质量与验证](09-quality-and-testing.md)。
