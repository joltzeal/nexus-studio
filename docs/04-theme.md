# 主题与交互规范

## desktop-v2 原生窗口（2026-11-19）

`apps/desktop-v2` 复用 ShardBrowser Launcher 的 ShardX UI Kit。下文旧主题章节为 0.1 历史说明。

`tauri.conf.json` 为开发和发行统一声明 `titleBarStyle: Overlay`、隐藏标题文字、
原生红绿灯位置和窗口尺寸。macOS 保留系统窗口装饰与原生按钮，WebView 内容延伸到
标题区，主壳层用上游 `shellPadClass()` 留出 38px 顶部空间；顶部与页面底板均使用
`--bg-canvas`，不另外画一条固定白色或深色标题栏。空白处拖动和双击缩放沿用上游
处理，控件、输入框及 portal 菜单不会触发拖动。

Tauri 配置在创建窗口时生效。修改后重启完整的 `tauri dev` 进程，以重新加载配置。

Windows/Linux 的 v2 主窗口在 Rust setup 中移除系统标题条，并挂载上游
`ShellWindowControls`，保留最小化、最大化/恢复和关闭语义。
`capabilities/window-chrome.json` 仅向主窗口与现有自动化辅助窗口授予拖动、最小化、
切换最大化和主题设置权限；关闭权限沿用现有 capability。

原生根节点挂载 `NativeThemeSync`，同步应用所选浅色/深色到窗口外观；跟随系统时
调用 `setTheme(null)` 解除固定外观。启动 HTML 的临时内联 `color-scheme` 在样式加载后
移除，后续由 `data-theme` 的 CSS 驱动，避免主题已经改变但原生表单/滚动控件仍用旧配色。
主题命令桥、窗口文件拖放/选择保护、焦点滚动留白及滚动条活动监听也接入原生入口。
缩放和减少动态效果仍由现有设置初始化模块恢复，本轮不重复安装其监听。

验证包括窗口配置/权限回归、拖动判定测试、JSON schema 校验，以及真实 v2 前端入口的
受控 IPC 浏览器检查：macOS/Windows 前端分支、浅深色和系统切换、主题命令、窗口按钮、
标题空白拖动/双击及按钮点击不拖窗。浏览器截图不包含系统红绿灯，也不能证明 AppKit、
WebView2 或 Windows 实机窗口行为。按仓库约定未构建应用、未编译/测试 Rust。
窗口初始化修改需要加载新原生二进制，不能只靠前端 HMR。修改 Tauri 配置时应完整
退出并重启 `tauri dev` 父 CLI；仅重启 Rust 子进程不保证刷新 CLI 缓存的额外配置。

本轮定向 7 项配置/拖动回归、ESLint、Prettier 和改动 Rust 文件的 rustfmt 检查通过。
全量前端 Node 检查为 185/199，14 项未通过：13 项仍引用缺失的旧后端/团队服务路径，
另一个 `plugins/ui-session.test.ts` 缺少本地 `@nexus/plugin-sdk/dist/ui.js` 构件。
无产物 TS 检查也仍有测试 Node 类型、既有预览 BlobPart 等诊断；本轮修改的业务文件无诊断。
未为这些无关检查修改依赖、生成构件或调整旧测试。

后续针对旧 CLI 缓存的修正已通过 8 项 Node 配置接线/拖动检查、定向 ESLint 与
Rustfmt。另添加 3 项 Rust 行为回归，覆盖旧 v2 配置、其他窗口及旧版/Preview 入口隔离；
按仓库约定未运行 Rust 测试，原生标题栏外观仍须使用新二进制验收。

## 当前设计方向

0.2 主壳层和窗口空状态以 ShardBrowser Launcher 的页面结构为参照，
保留 Raccoon 的 shadcn/Radix 组件及窗口、分组和插件逻辑。参考源码为 MIT 许可；
仅引入带许可文件的 Inter Variable 字体，不复制其商标和厂商业务逻辑。
工作区窗口底板留 8px，中性灰上放置白色侧栏与内容面板（深色模式为分层深灰）；
侧栏 232px、折叠后 56px，页标题 18px、正文 13px、导航项 28px。
滚动由侧栏目录和内容面板各自管理，页面与表格不使整窗横向溢出。
共享组件使用 8px 控件圆角、12px 面板圆角、柔和状态背景与明确的键盘焦点。
以指纹浏览器工作台的高密度操作为目标，不使用营销式大标题、插画、装饰贴纸和虚构图表。
参考 ShardBrowser 的面板比例、列表密度和状态对比度，但保留 Raccoon 的浏览器工作区、插件导航和现有交互。
历史 [Paper Play 概念图](design/paper-play-concept.png) 不作为布局验收基准。

## 色彩与主题

所有 token 集中在 `apps/desktop/src/theme.css`，组件使用语义变量。壳层、窗口页和设置导航使用 Tailwind 类；`legacy-pages.css` 仍保留尚未迁移的业务页 CSS，不再向其中追加壳层布局。
默认窗口底板 `#f5f5f5`，正文 `#171717`，侧栏与内容卡片白色，主操作色 `#535efd`。
边框为中性灰透明色，辅助文字 `#696969`，选中背景为低对比度中性灰。
外观设置中保留用户可选的珊瑚、石墨、鸢尾强调色，不能把它们作为卡片装饰。
状态色与品牌强调色分离，未连接状态使用中性样式，不暗示环境已启动。
深色使用根 `.dark` 与相同 token。默认浅色，也可跟随系统。
颜色不能成为状态的唯一表达方式；同时提供文字、选中态与焦点。

## 信息架构

侧栏顶部是 Raccoon 品牌、折叠按钮和浏览器工作区下拉菜单。每种浏览器提供方即一个工作区，各有自己的窗口与分组。
固定导航为搜索、全部配置、代理、指纹、扩展、书签、自动化和 ProxyShard；其中尚无 Raccoon 功能的入口显示明确的占位页。代理插件可用时，代理入口打开插件。
中部可滚动区域为文件夹、视图、插件中心及已启用插件的动态目录；底部固定回收站、设置、支持版本信息和接入状态。
侧栏可折叠为图标栏；图标有可访问名称与悬停标题。侧栏纵向可滚动，桌面宽度下不出现横向滚动。
主内容面板不再有面包屑顶栏；每个页面自行呈现 52px 标题区。窗口空白安装时展示居中的三步引导，已有窗口时呈现筛选与表格。
设置页卡片填满主内容区，由卡片内部的分类栏和内容区独立滚动。
窗口页：52px 页面标题和创建操作；非空时右侧搜索、分组与账号筛选、显示列、批量操作、独立滚动列表及分页。
列表参照 ShardBrowser Profiles 的无边框 tile、32px 黏性表头、紧凑分隔与中性选中态；Raccoon 账号、代理和行操作需要更多内容，当前行高为 44px，不能宣称与上游 36px 行逐像素一致。
表格包含窗口名称及备注、平台、所属分组、代理方式、状态与增删改查操作。
分组页采用轻量卡片，显示名称、数量和窗口摘要，提供新建、重命名和查看。
插件页按能力展示，不伪装成真实插件商店，不展示虚构下载量或评分。
应用设置包含外观、工作区和关于，使用普通设置表单，无装饰插画。

## 字体、尺度与密度

本地字体：Inter Variable、Noto Sans SC Variable，等宽为 IBM Plex Mono。
不依赖外部字体 CDN。页面标题 18px，面板标题 13px，正文及操作 13px，辅助信息 11–12px。
默认侧栏 232px，折叠后 56px，页面标题行 52px，内容内边距 16–20px，面板圆角 12px。
主内容区自适应填满侧栏以外的可用宽度，不使用固定最大宽度和自动居中外边距。
页面自行设置内容留白，直属页签滚动区域延伸至应用底部；
底部留白放在滚动内容末尾，只在滚到底时出现，不固定占用视口高度。
使用独立滚动区域的插件继续填满可用高度，表格横向溢出只在自己的容器内滚动。
窗口页的到期检查与恢复通知采用 12px 纵向间距，并与统计区相隔 12px；空通知容器隐藏。
主要控件 32px，侧栏导航项 28px；额外紧凑密度控件为 28px。
业务卡片使用 16px padding；Dialog 使用 p-4 / gap-4，表格单元格上下 8px、左右 12px。
共享基础组件沿用 shadcn/Radix，但通过语义 token 与紧凑变体对齐当前工作台布局。
外观表单在足够宽时采用标签与控件同排，窄屏改为上下排列。
表格随数据横向溢出时局部滚动，不使整页横向溢出。
窗口表格底部分页复用账号池的紧凑控件尺度，条目范围、每页条数和翻页操作在窄屏自动换行。
避免粗重分隔线、重阴影、渐变、浮雕按钮或多层卡片嵌套。

## shadcn 组成规则

使用官方 CLI 安装的 Radix / Nova、Tailwind 4；图标统一由 Hugeicons Free 经 `components/icons.tsx` 提供，与 ShardBrowser Launcher 的图标来源一致，不再依赖 Lucide。
组件主题通过 token 调整；导航的 navigation、设置的 appearance / swatch / segment 是正式变体。
表格使用 Table，表单使用 FieldGroup / Field / FieldLabel，选择使用 Select 或 ToggleGroup。
SelectItem 必须位于 SelectGroup；TabsTrigger 必须位于 TabsList。
弹窗必须有 DialogTitle 和 DialogDescription，并保留 Radix 的焦点管理。
恢复默认使用 AlertDialog。异步状态、错误、可重试操作必须可见。
按钮图标使用 `data-icon`，不在业务组件随意重设图标大小与颜色。

## 反馈与提示

复制、保存、收藏这类瞬时结果统一用右下角 toast，不在页面正文里追加“已复制”一类文字。
toast 由 `components/ui/toast.tsx` 的模块级 store 提供，`<Toaster />` 在应用根挂载一次，
页面任意模块可直接调用 `toast.success/error/info`，不需要 Provider。
同一句提示不会叠成两个；最多同时显示 3 条，成功 2.6 s、信息 3.6 s、错误 5.2 s 后自动消失。
成功与信息用 `status`，错误用 `alert`，都可以手动关闭；图标颜色分别取 success / destructive / primary token。
需要保留上下文的结果（例如写入文件的完整路径、上游返回的条数说明）仍留在页面里，不塞进 toast。

## 页面行为与响应式

创建、编辑、删除和分组整理通过 Rust 写入 SQLite，外观与工作区偏好使用 localStorage。
窗口详情只展示资料；真实启动与代理检测由各自命令获取结果，不能用本地资料替代运行状态。
插件卡片的状态与按钮反映宿主真实结果；安装、授权与执行由桌面宿主处理。
桌面最小窗口 960 × 700；窄屏浏览器预览用于检查布局弹性。
700px 以下侧栏保持 56px 图标栏，工作区切换和设置入口仍可使用；表格保留局部横向滚动，卡片单列排列。
页面标题下不放重复介绍，卡片不放无操作价值的副标题；字段标签、操作限制、真实状态、错误及危险确认仍须显示。
动效只有短暂淡入与 4px 位移；系统减少动态效果始终优先。
每次变更检查桌面与窄屏、键盘、弹层、长文本及保存错误状态。
