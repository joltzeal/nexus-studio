# Vinted 账号读取工具与回填方案

日期：2026-11-14。状态：读取工具、宿主策略、账号持久化和界面已接入源码。
本页依据用户提供的 current、wardrobe、wallet 和 bank_accounts 响应；
没有使用真实登录环境验证接口、Cookie 范围、跨域响应或财务结果。
已有账号池契约见[当前账号池实现](24-vinted-accounts-plugin.md)，
整体流程见[业务方案](47-vinted-business-workflows.md)。

## 1. 接口与职责

以下先支持美国站，不从站点字符串自动推导其他市场的财务域名。
工具名表示 Ecom Agent 内部职责，通过已绑定任务调用，不开放任意 URL 请求 RPC。
账号池的“检查账号”入口创建独立 `inspect_accounts` 任务。

| 内部工具                   | GET 目标                                                                                     | 用途                                   |
| -------------------------- | -------------------------------------------------------------------------------------------- | -------------------------------------- |
| `account.inspectCurrent`   | `https://www.vinted.com/api/v2/users/current`                                                | 核实身份、登录态、封禁、公开资料和主页 |
| `account.readWardrobe`     | `https://www.vinted.com/api/v2/wardrobe/{vintedUserId}/items?page={page}&per_page={perPage}` | 商品证据、发布基线和发布后核对         |
| `account.readWallet`       | `https://api.www.vinted.com/ledger/wallet/balance`                                           | 可用与待结算余额                       |
| `account.readBankAccounts` | `https://api.www.vinted.com/payments/public/api/bank_accounts`                               | 当前账号收款账户列表                   |

`vintedUserId` 使用 current 已确认的 Vinted 用户 ID。
它与 Raccoon 的窗口 UUID、账号 UUID、厂商 profile ID 均不相同。
所有工具通过宿主绑定上下文取得账号和窗口，调用者不能用任意 URL 或用户 ID 更换目标。

只读账号检查流程：

```text
进入目标账号与窗口的只读任务
  -> current 核对身份、登录态和封禁
  -> 保存主页及明确的官方状态
  -> wardrobe / wallet / bank_accounts 按需有界读取
  -> 财务结果写回前再次核对 current 身份
  -> 分域保存事实与回执
  -> 释放窗口执行资源
  -> 使用经过清洗的公开商品证据更新可选画像
```

同一窗口内的浏览器请求串行执行，不抢占发布中的页面。
掉登、身份不符或明确封禁时终止本次后续采集，并保存能够核实的状态。
发布任务不要求每件商品都重复查询财务资料：
窗口发布只做必要的登录态检查、发布操作及结果核对，
完整账号资料和画像刷新使用独立检查任务，避免占用上架链路。

## 2. 浏览器与网络边界

### 默认同源边界

现有 `packages/browser-runtime/src/automation.ts` 在页面中执行 fetch，
要求目标与页面同源，并使用 `credentials: 'same-origin'`。
默认路径继续限制同源。两个财务接口使用下述独立策略；
URL 的主域相同不等于浏览器同源，不能用普通请求绕过该限制。

### 已接入的财务读取策略

保留默认同源策略，新增由宿主校验、仅作用于当前任务的有限读取策略：

- 仍由目标窗口的真实页面发出 GET，复用该窗口的会话和代理。
- 美国站财务读取仅允许准确的 `https://api.www.vinted.com` origin，
  以及表中两个准确路径；不接受任意子域、端口、方法或重定向。
- 目标策略由插件的固定平台适配声明，经宿主权限、市场范围与租约校验。
  核心只处理通用的 origin、路径、方法和预算，不维护 Vinted 业务字段或选择器。
- 跨域 GET 使用 `credentials: 'include'`，继续遵守浏览器 CORS 与 Cookie 规则。
  读取前后确认页面仍是绑定站点；禁止 `no-cors`、浏览器关闭安全策略或 Node 直连回退。
- 不复制 Cookie 或令牌到应用网络客户端；不假设仅改 credentials 就必然能通过服务端校验。
  若真实页面还需要合法请求头或其他会话机制，先记录并验证该机制，再做有限适配，
  不凭样例编造认证头，也不开放任意请求头注入。
- 必需代理失败仍阻断；财务接口 401/403、CORS 失败不能直接改成掉登或封禁。
  掉登仅依据 current 的精确 `106/access_denied` 规则。

策略已同时接入 SDK、Rust 网关与 browser-runtime，受控测试覆盖协议失败；
Rust 编译及原生测试交给 CI。插件仍不能用任意绝对 URL 绕过来源或窗口作用域检查。
美国站之外返回不可用，不推导其他市场的财务域名。

跨域规则参考 [MDN Using Fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)；
资料仅解释浏览器机制，不证明 Vinted 已允许这些跨域请求。

## 3. current 与主页

先解析 HTTP/业务状态，再按[技术设计](superpowers/specs/2026-11-14-vinted-listing-tools-design.md)
核对用户 ID 与绑定。精确的掉登响应没有 user，不能伪造身份后回填主页。

| 来源字段                       | 保存或使用方式                                     |
| ------------------------------ | -------------------------------------------------- |
| `user.id`                      | 规范为正整数字符串，作为身份核对依据               |
| `user.login`                   | 核实账号身份；不作为可改绑窗口的指令               |
| `user.profile_url`             | 验证后写入账号 `homepageUrl`，来源记录为 current   |
| `user.is_account_banned`       | 明确 true 时写官方封禁证据；false 不单独解除原阻断 |
| 国家、币种、验证标记与公开统计 | 保存有界事实投影，明确缺失值与来源                 |

主页必须为对应市场的 HTTPS URL，路径严格属于 `/member/<相同用户ID>`，
允许该 ID 后的昵称后缀；拒绝用户名密码、异常端口、查询凭据、fragment 和外站跳转。
已有主页或已确认平台 ID 指向另一人时返回身份冲突，不自动改绑。
字段缺少、null 或无效时不清空旧主页、不拼接一个假定链接。
如果账号尚无可核对的 Vinted 身份，先完成独立身份确认；不能仅凭当前窗口返回的主页
自行证明该窗口属于某条导入账号。

新主页、身份观察和该操作回执在账号池同一次存储变更中保存。
沿用现有主页校验与订单查询调度入口：符合现有规则时可启用查询，
保留用户显式暂停、Bark 配置与已有订单去重记录，不重新创建一份监听任务。
保存失败返回未保存，不用整条账号的旧快照覆盖新编辑。

## 4. wardrobe 数据投影与分页

本次已读取用户粘贴的本地 JSON：包含 2 项商品、pagination 和 `code: 0`。
不把这两项样例或其所有者、标题、图片链接复制到仓库。

| 原字段                                                               | 用途与保留方式                                                  |
| -------------------------------------------------------------------- | --------------------------------------------------------------- |
| `id`、`user_id`、`user.id`                                           | 商品 ID 去重及所有者核对；多个所有者字段必须一致                |
| `title`                                                              | 有界文字，用于商品摘要和发布结果对照                            |
| `price.amount`、`price.currency_code`                                | 商品自身价格，保留十进制字符串及币种                            |
| `total_item_price`、`service_fee`                                    | 包含其他费用的金额，不当作商品发布价                            |
| `url`、`path`                                                        | 仅保留核实属于对应站点及商品 ID 的链接                          |
| `photos`                                                             | 发布核对时保留有界图片 ID、首图及必要原图引用，不复制全部缩略图 |
| `brand`、`size`、`status`                                            | 仅作为平台商品属性；本例 status 是成色                          |
| `is_closed`、`is_hidden`、`is_reserved`、`is_draft`、`is_processing` | 各自保留已观察布尔值，不合并成已售                              |
| `item_closing_action`                                                | 保留有界已知证据；本例全部为 null，没有已售状态映射证据         |
| `transaction_permitted`、`can_edit`                                  | 权限或交易提示，不作为登录、所有权或售出状态的唯一依据          |
| `pagination`                                                         | 校验当前页、总页数、每页数及条目数，保存扫描完成性              |

有明确且已验证的售出证据时才标记已售。
`is_closed: true` 可能只说明关闭，不能直接推导成交；
`is_closed: false` 也不单独证明商品当前允许出售。
本轮没有已售样本，不预建未经验证的 `item_closing_action` 值映射。

### 两种读取模式

- 画像样本：有界取得商品，标记 `sample` 与覆盖数量，不能据此声称已扫全店。
  沿用实际返回顺序，排序协议未验证时不把页首商品声称为最新发布。
- 基线与核对：按需分页，保留已见 ID、扫描范围和开始时间；只有满足完整性条件才标记
  `complete`。到达预算、失败、页码异常或列表在扫描间变化时标记 `partial`，
  不能把缺少某 ID 当作商品已删除，也不能据此直接提交第二次。

初始每页最多 5 项，单次扫描最多 100 页或 500 项，并受任务截止时间约束；
这些是本方案的初始预算，实施时可在该范围内调低。
保持当前浏览器响应 65,536 字节限制，不为缩略图放开通用传输上限。
超限时可降低 per_page 并从第一页重新建立扫描；最低一项仍超限则返回明确的
数据不可读取结果。不能在中途更改 per_page 后接着原页码、造成漏项并报告完整。
页数与元数据只代表该次响应，不能把易变化的分页列表当作事务快照。

同一 item ID 去重，不重复计数。样例没有创建时间或商品分类 ID，
不从递增 ID、URL 文本、成色或页内顺序伪造这些字段。
只取得列表标题时，发布确认仍须读商品详情核对描述、图片和其他必要事实。
已知旧 ID 从当前列表消失也不能作为本次发布成功的证据。

完整商品明细不复制到账号记录或每个 LangGraph 检查点。
账号池保存扫描摘要、时间和画像使用的证据引用；发布任务只保存有界基线及确认依据。
wardrobe 的平台商品与商品库 UUID 保持分开，不能把平台旧商品自动认领为本次发布。

## 5. wallet 余额

| 原字段                                  | 账号池含义         |
| --------------------------------------- | ------------------ |
| `main.amount`、`main.currency_code`     | 可用余额与其币种   |
| `escrow.amount`、`escrow.currency_code` | 待结算余额与其币种 |

沿用十进制字符串校验，不转 JavaScript 浮点数、不补零、不四舍五入。
显式 `"0.0"` 是已读取的零，缺少、null、错误或未解析不等于零。
不将可用与待结算金额相加显示成可提现额。

财务观察保存为两个独立 Money 值，以下为语义示意，实际契约以公开包为准：

```ts
// 省略了实际契约中的修订和来源元数据。
type ObservedMoney = {
  amount: string
  currency: string
  observedAt: string
  source: 'official'
}
type AccountWallet = {
  available: ObservedMoney | null
  pending: ObservedMoney | null
}
```

成功读取哪项就更新哪项；另一项不可读时保留旧金额与旧币种、旧时间。
两项币种不同也可分别保存，界面明确分别展示；不拼接、不换汇。
原单币种 `balance` 契约已通过一次性数据升级迁移为独立金额，
按现有金额及各自证据逐项升级，不增加运行时双格式读取。
wallet 本身没有用户 ID，采集前后均需 current 确认同一账号；
核对失败时该次金额不应用到任何账号。

## 6. 收款账户

保存用户要求的字段，并保留每次成功列表的来源、时间和窗口绑定修订：

| 原字段                    | 保存方式                                     |
| ------------------------- | -------------------------------------------- |
| `id`                      | 平台收款记录 ID，规范为正整数字符串          |
| `name`                    | 平台提供的姓名，账号详情按 `hide_name` 展示  |
| `account_number`          | 平台返回的掩码字符串，保留原样               |
| `routing_number`          | 字符串；美国九位 routing number 保留开头的零 |
| `spending_type`           | 有界原始类型，不把未知类型伪造成 checking    |
| `user_id`                 | 必须与已核实 current ID 一致                 |
| `hide_name`、`is_default` | 保留明确的布尔值，不从列表位置推断默认项     |

校验列表中每个 user_id、记录唯一性、字段类型和整体预算。
任何条目身份不符时整次结果拒绝，不将“看起来正确的几项”写入另一个账号。
没有默认项或多项声明默认时展示平台原事实并提示异常，不擅自选第一项。

仅明确成功且结构完整的 `bank_accounts: []` 才清空当前收款列表，
并显示已检查、未绑定。字段缺失、null、解析失败、掉登或跨域失败均保留旧列表。
默认账号表格显示绑定数量、默认项掩码和检查时间；完整姓名和 routing number
放在账号详情中，不将金融资料展开进普通列表、toast、模型输入或页面诊断。
不预建添加、修改或删除银行账户的写接口。

## 7. 写入、时序与跨插件投影

账号池继续使用现有明文私有存储，Rust 是 SQLite 唯一所有者。
新数据不能只保存在 Agent 检查点，必须通过受控账号观察写入对应账号。
不使用通用账号 `save` 回写一份过期的完整对象。

每个观察操作带稳定 operationId、账号 UUID、窗口 UUID、绑定修订与来源；
同操作重试返回原回执，不同输入复用同 ID 拒绝。
账号池分别为主页/身份、窗口登录、钱包两项、收款列表和模型分析维护修订与采集顺序。
以采集开始前预留的顺序核对迟到结果，不能让晚返回的旧读取覆盖新结果；
展示时间使用真实观察时间，不人为递增时间以绕过更新门槛。
写入和操作回执同次落盘，解绑、改绑、删除及存储错误均阻止错误回填。
收款名单替换与钱包增量更新分开，允许一项成功而另一项失败。

`vinted.accounts.observations.reserve/record` 使用严格 DTO，
主页和财务域已同步接入公开 schema、宿主窄字段校验和桌面 DTO。
观察先取得持久化序号，数据与回执同次保存；重放同一回执不重复写盘。
普通完整账号编辑另带 `expectedUpdatedAt`，防止旧表单覆盖后台新状态。
内部读取工具仍不自动成为可请求任意站点的外部权限。

`account.agent.snapshot` 必须继续采用显式投影，不返回姓名、账户号、routing number
或完整财务响应；发布与画像不需要这些字段。
把银行数据加入账号存储时不能因复用整个 `observation` 对象而泄露到 Agent/模型。
金融值可以在受控调用中瞬时传给账号池，普通任务检查点与日志只保留状态、
来源和回执引用，不重复完整银行记录。
配置导出仍不混入业务记录；窗口迁移若携带账号业务附件，
同步新字段并避免把旧窗口登录观察当作新设备仍已登录。

## 8. 验收与未验证项

| 范围     | 关键验证                                                              |
| -------- | --------------------------------------------------------------------- |
| 主页     | 同 ID 昵称变更、空链接、外站、错误身份、并发编辑、订单查询不重复启用  |
| wardrobe | 两种读取模式、分页变化、超过预算、缩略图超限、重复 ID、错误所有者     |
| 商品状态 | 成色与销售状态分离、关闭不等于已售、未知 closing action、不伪造成交   |
| 余额     | 零、缺失、非法金额、部分成功、不同币种、采集前后账号变化、迟到结果    |
| 收款账户 | 多条记录、无默认/多默认、空成功列表、错误所有者、前导零、失败保留旧值 |
| 网络     | 同源默认不变、两个精确跨域 GET、CORS 失败、重定向、代理失败、租约失效 |
| 持久化   | 稳定操作重试、写入失败、进程重启读回、旧数据一次性升级、分域修订      |
| 投影     | Agent/模型/日志不包含银行资料，账号详情按需显示，迁移关系不串号       |

接口形状和字段语义来自用户提供的样例，不等于公开稳定协议或真实平台测试。
真实 CORS、认证机制、已售状态映射、完整分页与默认项异常尚待受控环境验证。
没有对真实账号读取或发布商品，不涉及转账或更改收款方式。
实际测试与发布结果见[质量记录](09-quality-and-testing.md)和[发行记录](20-desktop-release-and-updates.md)。
