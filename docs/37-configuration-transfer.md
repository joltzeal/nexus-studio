# 配置导入导出

主程序从 `0.1.21` 提供此入口，配套 AI 生图 `1.4.4`、Vinted 监控 `1.1.3`、
SIM8 `1.0.3`、代理池 `1.0.3` 和地址生成器 `1.0.1`。

## 使用方式

进入「应用设置 → 配置迁移」，选择配置后导出 JSON 文件。另一台设备在同一页面选择文件，
查看文件包含的配置，选中需要恢复的项目，再点击「导入所选」。
选择文件只读取和预览，不修改当前设置。原生文件对话框取消后不显示导出成功。

| 项目          | 迁移内容                                                   | 不包含                                                          |
| ------------- | ---------------------------------------------------------- | --------------------------------------------------------------- |
| 外观与工作区  | 主题、强调色、界面密度、减少动画、工作区名称               | 当前页面和筛选条件                                              |
| 应用代理      | 直连、系统或手动代理模式与地址                             | 另一台电脑的系统代理设置                                        |
| AI 生图       | 服务商地址、密钥、识图/生图模型、超时和响应方式、最近选择  | 图片、生成记录、运行中任务、机器路径                            |
| SIM8          | 接口地址、实际 Token                                       | 号码池、订单、账户信息缓存、到期提醒关闭记录                    |
| 地址生成器    | Google Maps Key                                            | 地址查询缓存和导出文件                                          |
| 代理池        | 默认代理的连接参数及密码、风险检测开关、缓存时间与 API Key | 其余代理库存、订阅及检测历史                                    |
| Vinted 监控   | 采集代理列表及密码、默认采集代理                           | 监控任务、商品、商家和采集记录                                  |
| Vinted 账号池 | 查询间隔、Bark 服务地址、设备 Key 与启用状态（插件 1.1.0） | 账号、绑定、衣柜基线、候选商品和推送历史                        |
| 邮箱管理      | token 刷新及自动收信的独立开关、间隔                       | 邮箱账号、密码、client ID、token、邮件、收信/刷新记录和账号关联 |

共享货源及窗口同步当前没有独立配置项，不将业务记录当作配置搬迁。
邮箱自动收信配置属于当前开发版本；已发布邮箱 `1.0.0` 仅迁移 token 刷新设置。
账号池配置范围与自动查询行为见[订单查询与 Bark 提醒](38-vinted-account-order-watch.md)。
文件不携带浏览器接入、激活码、内核、窗口或 Cookie；窗口环境继续使用独立的加密迁移功能。
配置文件是明文，包含所选配置中的实际密钥值，不包含本机文件引用或 Keychain 项。

## 写入规则

- 插件通过 `configuration.export / configuration.validate / configuration.import` 管理自身配置。
  主程序只运输版本化 JSON，不读取插件目录，也不打开插件业务文件。
- 安装且正在运行、已声明全部三个方法并有已授予能力的插件才可选择。
  缺失插件和不支持迁移的旧插件在设置中标明，不能导入成功后静默遗漏。
- 文件先做严格结构、版本、重复插件 ID、大小和应用配置校验；
  所选插件再全部调用只读 `validate`，全部通过后才开始写入。
- 写入不是跨进程原子事务。逐项显示真实结果，成功项不重复选中，失败项保留以供重试。
  应用代理最后写入，因为更改代理会重启插件进程。
- AI 服务商和采集代理按稳定 ID 合并，更新同 ID 的配置，保留本机其他条目。
  默认代理连接在目标代理池去重或新增，再设置为默认；不覆盖现有窗口绑定的代理。
- SIM8 导入不请求账户接口或购买号码。导入会清除旧账户缓存，下次正常请求仍由服务校验 Token。
- 凭据先创建新引用，插件文档落盘成功后才清理旧引用；文档写入失败保留旧值并清理新引用。
  未引用凭据清理失败不改变已提交的配置结果。
- 外观和工作区通过现有偏好写入器保存，插件继续使用各自的明文私有存储；
  不复制整个 SQLite 或私有目录来替代导入。

## 文件与接口

归档 `format: "nexus-configuration"`、`schemaVersion: 1`，包含 `exportedAt`、
可空 `preferences`、可空 `networkProxy` 以及 `plugins` 数组。
插件条目为 `{ id, name, version, configuration: { schemaVersion: 1, data } }`。
空值表示未导出该项，导入不因此重置目标设备。
插件自己的 `data` 必须完整表达可迁移配置，密钥引用须解引用为实际值。

文件最多 8 MiB，最多 64 个插件；单个插件配置 JSON 最多 128 Ki 个字符，
为宿主 1 MiB 的单行协议保留空间。未知版本和额外字段直接拒绝，不做旧格式兼容。

`configuration_file_export` 接受经过前端校验的 `content`，打开保存对话框，
在同目录临时写入并同步后替换目标文件；只有成功写入后返回绝对路径。
`configuration_file_import` 打开选择对话框，限制读取量、验证 UTF-8 和顶层格式，
返回 `{ name, content }`，前端继续完成完整 schema 和插件校验。
原生命令不接受任意读取路径，取消返回 `null`。

SDK 的 `@nexus/plugin-sdk/configuration` 只对外导出编译后的 JS 与声明文件，
测试使用独立源码映射；安装插件不依赖 Node 在 `node_modules` 执行 TypeScript。
通用接口使用插件既有能力，不增加插件代码执行权限，也不自动安装文件指定的插件。

## 验证边界

单元测试覆盖跨空存储恢复、配置与业务记录分离、无效版本/引用拒绝、
密钥失败回滚、整批预校验、逐项写入结果和文件选择后的显式导入。
未运行本地构建、打包或 Rust 编译。原生文件对话框、双平台写入替换和真实服务请求
需由桌面验收与 CI 确认，不以 TypeScript 测试代替。
