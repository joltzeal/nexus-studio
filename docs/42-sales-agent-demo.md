# Ecom Agent 交互原型

## 当前范围

按照本轮“先做 demo 页，操作后矫正”的要求，先提供独立开发页面：

`http://127.0.0.1:1420/__demo/sales-agent`

入口仅在 Vite 开发模式开放，不注册安装记录或修改正式插件导航。
页面沿用现有纸白钴蓝主题、紧凑 shadcn 控件和自适应表格。
正式窗口、账号池、商品管理、AI 生图、插件宿主和 Rust 接口均未在原型中调用。
示例商品、账号、模型检查和运行结果都有明确的预览或模拟标识。

## 可操作流程

1. 选择任务预设、填写任务名称和指令、调整同时执行的窗口数。
2. 在“商品与窗口分配”查看左侧本次商品、右侧执行窗口。窗口卡片展示账号、
   浏览器、主营标签、评价、账号状态、可用与待结算余额。
3. 从“商品库选择”添加示例商品；按独立商品 ID 去重，每件商品代表一个商品及其整组图片，
   不再以 AI 生成记录或批次作为 Agent 的商品来源。
4. 点击“模拟 AI 补全”补齐示例空缺字段，保留手工填写的内容。
5. 点击“批量编辑资料”：有勾选时编辑勾选商品，无勾选时编辑全部商品。
6. “逐件资料”可编辑英文标题、描述、价格、币种、分类、成色、品牌与尺寸；
   “统一修改”仅将勾选字段应用到本次编辑商品，然后统一保存。
7. 从左侧拖拽单件商品到右侧窗口；勾选多件后拖动其中一件可整批分配。
   也可勾选商品后点击目标窗口的“分配”，全程支持键盘操作。
   已分配商品留在左侧显示目标窗口，右侧窗口内同时显示对应商品。
   两侧使用相同商品首图，右侧分配项同时展示缩略图与名称，方便快速区分。
   从窗口拖到另一窗口完成改派；拖回左侧、点击商品旁的叉号，
   或勾选后“取消分配”可解除关系。下方资料表格同步显示当前分配。
8. 点击“运行前检查”查看模拟的图片检查与文案改写结果。
9. 点击“预览并模拟运行”确认分配；进入运行记录，按窗口查看进度、结果和日志。

Post Listing、Message 和 Account Check 均能预览窗口任务分发。
后两项仅模拟按窗口执行，不提供真实会话收发或账号池写回。

## 已体现的规则

- 一件商品只能分配给一个窗口；重复选取相同来源商品会被阻止。
- 一个窗口可以接收多件商品，并按顺序执行；不同窗口受并行数控制。
- 移除执行窗口后，原属该窗口的商品变成未分配，不偷偷改到其他账号。
- 标题、描述、有效价格、成色、窗口分配和运行前检查不足时不能开始上架模拟；分类为选填。
- 图片检查不通过的商品跳过；其他商品继续。
- 示例营销式文案被改成自然英文，使用当前编辑后的品牌与尺寸；
  用户手工修改过的文案保留。修改资料会使原检查结果失效，需重新检查。
- 账号为 blocked 时，该账号全部后续任务停止，其他账号继续执行。
- 开始时复制一份运行快照，模拟期间锁住准备表单。停止后保留已完成结果。

## 列表与大量窗口

左右两侧均为 460px 高的独立列表容器，内部滚动，不因窗口或商品数量增加而撑高分配卡片。
商品支持搜索和“全部 / 未分配 / 已分配”筛选；全选只影响筛选后的商品，
其他已勾选商品仍保留，总选择数包含隐藏的选择。分配或取消分配后清除勾选。
窗口支持按名称、账号、浏览器、标签搜索，也可仅看有分配商品的窗口。
窄屏改为上下排列，两个列表仍固定高度；点击或键盘分配不依赖拖拽。

“体验 100 个窗口”载入并选中 100 个明确的示例窗口，保留商品资料与原有分配。
“恢复 4 个窗口”选中基础四个窗口；属于被移除窗口的商品回到未分配，
不自动转给其他账号。额外窗口身份是确定的，重复切换不会随机改变 ID。
“选择窗口”弹窗提供搜索和区域内滚动；筛选全选不影响隐藏窗口的选择。
执行确认弹窗同样限制高度，100 个窗口时在弹窗内滚动。

Message 与 Account Check 只保留固定高度的执行窗口列表，不显示商品分配区。
“待上架商品”资料卡、批量编辑与检查流程保留，分类继续选填；
表格中的窗口列用于回显关系，不再提供另一套逐行下拉分配入口。

## 示例与实际能力的区别

`demo-data.ts` 包含六件商品与四个基础窗口，也可生成固定身份的 100 个示例窗口。
其中咖啡杯有缺失资料，
针织开衫有待改写文案，帆布画预设图片检查不通过，一个账号为封禁状态。
图片使用随原型提供的本地示例首图，不读取设备或真实插件中的素材。
所有补全、检查、改写和计时执行均为本地固定规则，没有调用识图模型、Jev 或生图模型。
它们只能用于评审页面与流程，不能证明实际模型能准确判断图片或账号状态。

资料和最新一次运行只保留在当前页面内存中；刷新、关闭页面或点击“重置示例”会清除。
原型不写 SQLite、localStorage、Keychain 或插件私有目录，不需要设置密钥。
深浅主题切换同样只作用于当前预览。

本页未实现正式 Agent 的浏览器自动化契约、跨插件业务接口、余额与标签持久化、
真实执行恢复、模型调用和平台发布。后续实现建议见[Ecom Agent 架构方案](44-sales-agent-architecture.md)。

### 示例首图来源

`assets/product-covers.png` 是为原型生成的一张 3×2 商品图片图集，
依次为花卉铁皮画、米色开衫、蓝色陶瓷杯、植物帆布画、棕色手提包和条纹陶瓷盘。
生成方向为欧美家庭环境、手机随手拍、自然光和生活化摆放。
图片只说明示例商品身份，不代表来自真实库存，也不作为识图或图片审查的测试证据。
`ProductCover` 按商品的固定图集序号显示首图；拖拽和改派保留相同序号。
左侧商品、资料表格与右侧已分配项复用同一组件，右侧缩略图为 32px。
素材只由开发原型引用，不加入商品插件初始化数据。

## 商品库边界与后续接入

用户已确认先实现独立[商品插件](43-products-plugin.md)，Agent 后续消费商品 UUID，
不直接将 AI 生图记录用作商品。当前原型的商品选择与关系面板已按此语义调整，
保留明确标注的示例商品库；没有连接真实商品插件 IPC、读取其图片或写入真实商品。
正式 Agent 仍需通过公开契约获取稳定商品 UUID 和完整图片，并在运行时固定执行快照。
本轮完成的是可操作的关系分配演示，不是实际发布或浏览器调度接入。
