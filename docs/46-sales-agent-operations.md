# Ecom Agent 操作与恢复

本页说明 Ecom Agent 的日常操作、资料归属和异常处理。
架构见[Ecom Agent 架构](44-sales-agent-architecture.md)，实施与验证证据见
[实施审计](45-sales-agent-implementation-audit.md)及[质量记录](09-quality-and-testing.md)。

本次页面配套主程序为 `0.1.30`，插件为 Ecom Agent `1.0.1`、
商品管理 `1.0.1` 和 Vinted 账号池 `1.4.1`。
插件展示名为 `Ecom Agent`，使用机器人图标；内部标识仍为 `studio.sales-agent`。
插件发布状态与回执见[插件商店](25-plugin-market.md)，页面变化需要更新主程序。
插件启动时必须报告持久存储可用，设置才能跨进程重启保留。

## 准备账号与商品

先在窗口管理关联 Vinted 账号，再在商品管理中准备商品。
AI 生图生成的素材需要先导入商品管理，Agent 始终引用独立商品 UUID。
账号池保留用户资料；任务仅局部写回标签、摘要、评分、余额和观察到的状态，
不会用模型输出覆盖密码、手机号、邮箱关联或用户备注。

上架需要英文标题、英文描述、价格、币种、成色和图片；分类可留空。
缺少材质、尺寸、品牌或缺陷等商品事实时，应由用户补齐。
模型可以整理表达，不能编造事实。

在“创建任务”中选取商品与执行窗口，再拖拽商品到目标窗口，
或使用分配按钮。左右分配区域固定高度并在内部滚动。
每个目标商品只能分给一个窗口，窗口卡片显示待发布商品首图。
批量编辑只调整本批次使用的资料，不直接修改商品库原始记录。

商品库负责维护可复用的原始英文标题、描述和商品事实；
Ecom Agent 负责本批次的文案调整、发布前校验和必要改写。
本批次候选文案不会自动覆盖商品库，避免某个账号的要求改动所有后续批次。
商品选择弹窗右侧显示相对添加时间及真实上架次数，悬停时间可查看绝对时间与时区。
已有发布记录的商品仍受重复上架限制。

右侧执行窗口可按正常、待验证、受限、封禁和未关联/未知账号筛选，
与搜索、已选筛选和分页组合使用；切换筛选保留已选窗口和商品分配。
筛选只影响当前显示，封禁窗口仍不能选择、分配或派发。

确认后冻结浏览器绑定、账号身份、商品与图片、模型及执行设置。
后续修改商品库或模型设置不会悄悄改变运行中的批次。
实际发布成功后，商品管理显示已发布及使用窗口；分配、排队和模型判断均不算发布成功。

## 模型和执行设置

决策模型用于结构化判断，生成模型用于识图与英文文案。
决策测试验证判断协议；生成测试实际携带受控图片并验证视觉结果和英文输出。
测试会向用户保存的端点发出模型请求，可能产生服务商费用。
测试通过不代表平台账号已登录，也不保证所有商品判断都正确。

两个模型的地址、API Key 和模型名称均须完整填写。
无效或空地址会显示对应字段错误，不会中断保存流程或清空输入。
有未保存修改时，测试按钮显示“保存并测试”，持久化成功后才测试所选模型。
保存失败时保留输入且不发送模型测试请求；普通测试继续使用已经保存的配置。

窗口并发与模型并发分别设置。窗口派发还受到提供方设置上限、
窗口与账号互斥、已保留资源和平台冷却的约束。
提供方设置是本应用的调度上限，不能当作第三方许可证剩余席位。
同一窗口内的商品顺序执行；不同窗口在允许的并发内推进。

用量显示模型请求次数、成功与失败、累计请求耗时和服务商返回的 token。
请求明细按开始时间分页，显示决策或生成模型、状态、耗时和费用估算，
不显示模型密钥、请求体或浏览器连接信息。
服务商未返回用量时显示未知，不按零费用处理。
只有配置模型单价后才能估算费用；该估算不能代替服务商账单。
请求预算用于阻止继续申请模型请求，已经发出的请求和已经消费的费用无法撤回。
配置费用预算后，同一批次等待当前请求的费用回执再继续申请。
预算根据已知消费拦截后续请求；已经获准的单次调用仍可能超过剩余估算，
因此该设置不是服务商账单的硬上限。

## 运行前检查与草稿

运行前检查集中展示模型设置、窗口状态、账号绑定、商品资料、
图片元数据、资源占用和批次素材大小等问题。
检查通过只代表当前已保存资料可用于创建任务。
浏览器启动后仍须核对实际登录身份、当前账号状态和表单内容。
“保存了账号”不能被展示成“已验证在线登录”。

草稿与模板由 Rust 保存到 SQLite，带修订号。
其中仅保存稳定商品、窗口关系和用户编辑值，不保存 Cookie、CDP 地址、
模型密钥或图片字节。可保存尚未分配完成的草稿。
已编辑但尚未分配到窗口的商品资料也会保存，分配关系和编辑值分别核对。
载入后重新读取当前商品和窗口；已删除、已发布、封禁或不可见的来源会明确提示，
不能自动替换到其他商品或账号。

保存冲突或写入失败时保留当前表单。重新读取前应先核对资料，
避免覆盖其他操作刚保存的修订。

## 暂停、取消与人工接管

批次与单窗口都支持暂停、继续、取消和暂停并接管。
暂停停止后续派发；在途请求需要先收敛。
取消不撤销已经成功的刊登或消息，也不会删除真实发布历史。

“暂停并接管”先停止自动控制并隔离浏览器 actor。
只有隔离完成且状态允许时才显示可以人工操作。
仍在停止、隔离失败或提交结果不明时不能按已经安全释放处理。
同步控制中的隔离失败会返回错误，取消或暂停意图仍可能已保存；
需要先读取任务状态核对。窗口占用在持久化释放成功前保持锁定，
后台按有界退避继续核对，不会因返回错误提前释放或控制无关窗口。
厂商窗口中用户的手工动作无法被本应用完整识别，恢复前仍需要核对现状。

明确封禁停止该账号后续写入，其他健康账号继续。
网络错误、代理失败、普通 HTTP 403 和超时不会被直接当成账号封禁。
余额读取失败保留已有金额，不写成零。

## 商品审查与结果核对

“待处理与审查”集中展示需要人工检查的窗口。
展开商品可对比原始标题与描述、候选文案、判断原因和冻结首图。
未提交商品可以跳过、修订或确认继续；原始快照和已记录动作仍然保留。
修订后仍需经过正常内容和表单验证，确认继续不能绕过账号封禁。

已提交、结果不明或记录待同步的商品不能通过跳过、修订或确认来重新发布。
核对时先读已有动作回执；结果页丢失则有界读取本人近期刊登，
排除提交前已有商品，并核对账号、时间、价格、标题与描述等证据。
候选不存在、证据不足或有多个候选时继续等待处理，不能猜测成功或自动重发。
消息任务同样不自动重发结果不明的消息。

外部发布已经确认而商品插件暂时无法登记时，显示记录待同步。
恢复只重试登记，不再执行外部发布动作。
商品、窗口和账号页面的执行记录入口可查看各自关联的全部任务历史，
包括已经结束的任务；关联历史不局限于待处理任务。

安全的读取与推理失败按有限次数退避，等待时间和剩余次数持久化；
重启不重置已经消耗的重试次数。平台限流进入冷却。
发布和消息提交不使用这一重试机制。

## Bark 与任务链接

通知默认关闭。用户填写 Bark 地址、设备密钥并启用后，
按设置发送批次结束和需要处理摘要，普通步骤不逐条通知。
配置按用户约定明文持久化，不写 Keychain，不进入普通错误消息。

Rust 保存稳定通知 ID、尝试次数和发送收据；失败有限重试。
同一批次的同类摘要不会因页面刷新反复创建。
远端已接收但本地回执尚未保存时仍可能再次投递，不承诺跨服务端严格只送达一次。
用量面板可查看待发送、已发送或失败状态。

通知链接仅使用 `nexus://agent/<批次 UUID>` 打开对应任务。
链接不能执行发布、恢复或清理操作。
桌面链接注册依赖正式安装；开发网页预览不代表操作系统已注册该协议。

## 保留策略与清理

自动清理默认关闭。手动清理先预览保留天数、可清理批次数、
受保护数量和素材大小，再确认执行。
预览有有效期，执行前在事务中再次核对；状态变化时整次清理拒绝执行，
需要重新预览。

运行或暂停中的任务、未知提交、待同步记录、未释放资源、
在途模型请求和待发送通知受保护。
已确认商品发布事实单独保留，清理历史不能解除重复上架限制。
原批次的创建操作 ID 和内容摘要也会保留，清理后重放原创建请求仍会被拒绝，
消息任务不能通过清理历史再次发送。
素材目录删除失败保留清理收据，后续重试；返回的释放字节数以实际删除结果为准。
清理仅处理 Agent 历史和任务素材，不删除商品库、账号、窗口或浏览器资料。

## 应用退出与验证边界

任务在 Raccoon 运行期间执行。退出后保留已持久化的进度与收据，
重新打开时先核对浏览器控制权和外部动作，再恢复允许执行的步骤。
没有后台系统服务在应用退出后继续运行任务。

当前开发检查不包含本地构建、Rust 编译或测试、真实平台写入、
真实模型计费、真实 Bark 投递和 Windows 安装。
这些验收需要 CI 或受控设备与账号，不能用受控响应和浏览器页面测试替代。
