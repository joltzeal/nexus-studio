# 生图流式响应与请求等待时间

本节对应主程序 `0.1.18`、AI 生图插件 `1.4.0`。请求仍由插件后台执行，
页面通过已有记录接口读取状态；不会让一个长时间生图请求占用宿主 RPC。
主程序与插件需配套更新，实际验证与发布证据见[质量记录](09-quality-and-testing.md)。

## 服务商配置

AI 生图 → 模型配置中，每个服务商可以单独保存：

| 字段                  | 页面                     | 默认值与范围                                       |
| --------------------- | ------------------------ | -------------------------------------------------- |
| `imageTimeoutSeconds` | 生图等待时间，按分钟填写 | 默认 900 秒，即 15 分钟；接口接受 60–3600 的整数秒 |
| `imageResponseMode`   | 自动、流式、普通响应     | 默认 `auto`，另外可选 `stream`、`json`             |

既有服务商缺少字段时按上述默认值读取；编辑时省略字段保留当前值。
配置与其他服务商资料一起明文保存于插件私有文档，不引入新的凭据存储。
修改后必须先保存才能测试；等待时间或响应方式有未保存修改时，同样阻止使用旧配置测试。

自动模式对 `gpt-image` 家族及 `chatgpt-image-latest` 请求流式响应，
其他模型保持普通请求，不修改原模型名。自定义模型如支持标准 Images 流式协议，
可以明确选择“流式”；拒绝 `stream` 参数的兼容网关可选择“普通”后手动提交。
失败后不会通过改协议、改模型或重复 POST 自动回退。

`image.providers.list` 返回 `transportSettingsVersion: 1` 表明支持这些字段。
旧插件不具备该标记时，新页面要求更新插件后再修改请求设置，不能假报配置已生效。
RPC 方法仍为 21 个，没有新增模型角色。

## 请求与截止时间

文生图继续使用 JSON `POST /images/generations`，改图继续使用 multipart
`POST /images/edits` 与原有 `image[]` 字段。流式模式额外传 `stream: true`，
并允许 `text/event-stream` 与 `application/json` 响应；即使网关忽略流式参数、
返回普通 JSON，也直接解析同一次响应，不重复提交请求。

生成、改图、服务商生图测试和每个智能场景视角均使用已保存的生图等待时间。
每一次图片请求从提交开始计时，连接、响应体、流式事件和结果 URL 下载共用一个
AbortSignal 与截止时间；下载不重新获得整段等待时间。多视角仍逐张提交，
各视角各有预算，已有成功视角的保留与手动重试规则不变。

识图、场景规划和成片识图由 60 秒延长为 5 分钟；`/models` 连通性检查与
参考图远程下载仍为 20 秒。识图和随后的生图是两个独立请求，不共用一个预算。
主程序的网络预加载层也配套调整，避免 Node `fetch` 的默认头部或响应体超时
提前切断慢请求；直连、HTTP(S) 和 SOCKS5 继续遵守同一应用代理选择，
失败不切换直连，见[应用代理](26-application-network-proxy.md)。

截止时中止请求和正在读取的响应体，结束后清理计时器与 reader。
读取 JSON、SSE 或图片字节时发生的超时保留为超时，不再误报无效 JSON 或无效图片。
底层 `UND_ERR_HEADERS_TIMEOUT`、`UND_ERR_BODY_TIMEOUT`、
`UND_ERR_CONNECT_TIMEOUT` 也归为超时；错误页和服务商明确拒绝仍按实际原因处理。

## 流式解析

使用开源 `eventsource-parser@3.1.1` 解析 SSE，不自行维护分行状态机。
支持分块 UTF-8、CRLF/LF、注释心跳、多行 data 以及命名事件。

- `image_generation.completed`、`image_edit.completed` 才计为最终图片。
- 兼容网关没有事件类型、使用 `data: {"data":[...]}` 返回图片列表时也可读取，
  但需等待 `[DONE]` 或正常流结束，避免忽略图片后紧跟的错误事件。
- `partial_image` 和进度事件只用于保持读取，不保存为成片，不提前报告生成成功。
- 收齐请求数量的最终图片后关闭仍在发送心跳的响应；提前断流或 `[DONE]`
  没有提供完整图片时明确失败。
- 带相同 SSE `id` 的重复完成事件只计一次，不把重发事件当作另一张成片。
- 流中的 `error` 按既有脱敏流程处理，保留有界说明和请求标识，不输出
  Key、提示词、图片 Base64 或签名 URL。HTTP 200 不代表流内任务成功。
- JSON 与图片下载上限为 64 MiB；单个 SSE 事件缓冲最多 64 Mi 个字符，
  整条 SSE 字节上限为 256 MiB。
  即使未结束事件或不断发送心跳，也受内存限制与总截止时间约束。

结果继续验证 Base64 和 PNG/JPEG/WebP 签名后才保存。结果 URL 请求不携带模型 API Key，
仍沿用应用网络与同一截止时间。不会在断流后自动续传、重新生成或更换接口；
手动重试前应确认服务商是否已经完成原任务，避免重复费用。

## 兼容与验证边界

流式传输需要服务商和中间网关支持。客户端能够持续消费服务端提供的数据，
无法替服务端发送心跳，也不能覆盖网关自身的断连或任务截止时间。
当前不在页面逐帧展示中间预览；完成后仍通过原有记录、缩略图、详情和导出入口查看。
Chat 出图与异步任务接口不属于本次新增协议。

协议依据为 OpenAI 官方 SDK 的 `src/resources/images.ts` 中生成/编辑流式事件，
以及 eventsource-parser 3.1.1 的公开接口。自动化验证使用本地合成接口，
覆盖慢响应、分块、断流、错误、资源释放与代理路径；不访问真实付费服务商。
未执行的安装、Windows、原生 WebView 和真实兼容网关检查不能由这些结果代替。
