# 智能识图与多视角场景图

本功能属于 `studio.ai-image`。主程序提供交互与插件调度，识图、场景规划、
生图请求和记录持久化均在 AI 生图插件内完成。
基础模型配置、图片上传和商品来源关联见[AI 生图插件](22-ai-image-plugin.md)。

## 使用流程

1. 添加至少一张参考图，选择独立识图模型和用于识图的图片。
2. 填写商品约束，设置生成张数，点击智能识图。
3. 查看商品类型、材质判断、推荐场景与各视角提示词；可调整场景与提示词。
4. 确认后开始生成。每个视角分别生成一张图片，在记录中查看结果。
5. 某个视角失败时保留已经完成的图片，手动重试只补未完成的视角。

只有一张参考图也可以规划多张场景图。例如，客厅装饰画可规划正面挂墙、
带沙发的环境视角、轻微侧向视角和画面细节。视角数量为 1–4，
不要求每个视角都提供一张对应的参考图。
识图结果是模型判断；铁皮画与帆布画等无法从照片确认的材质应标明不确定，
不能把不可见的背面、厚度、尺寸、挂点或内部结构当作已知事实。

点击智能识图只请求识图模型。查看、编辑方案不会请求生图模型；
点击开始生成才提交生图任务。进入页面、从商品页导入图片或打开模型配置，
均不自动触发付费模型请求。

## 场景与提示词

识图模型读取所选的一张参考图、用户填写的要求和现有 100 个场景的目录，
返回商品观察、适合的场景 ID、推荐理由、公共提示词和各视角提示词。
场景必须来自插件现有预设，不能返回不存在的 ID。
中文标签和说明便于编辑，生图指令使用英文。

生成请求组合以下内容：

- 原图观察和不确定项，明确作为可能有误的资料。
- 用户选定的场景预设。
- 可编辑的公共提示词和该张图片的视角提示词。
- 用户原始附加要求，以及保留商品实际状态的约束。

默认保持欧美普通家庭的生活感和自然光，保留实际颜色、材质、图案、文字、
标识、瑕疵与成色。对挂画等商品，场景应服从商品用途，避免强行缩放、
改变画面内容或为摆放方式虚构配件。
这些是模型约束，不构成生成图与实物完全一致的保证。

每个视角单独调用 `/images/edits`，`n=1`，使用原有参考图。
不会将同一条提示词重复请求多张当作多视角，也不会把前一张生成图替换成下一张的原始依据。
使用已经完成的智能方案生成时，不再重复识别参考图。
不使用智能方案时，原有手动提示词、预设和生成前单图识别仍可使用。

## 插件接口

### 创建与读取方案

`image.plans.create`：

```ts
{
  providerId: string
  inputFileId: string
  requirements: string
  count: number // 1–4
}
```

立即返回 `{ plan }`，模型请求在后台执行。页面通过
`image.plans.get({ id })` 顺序轮询，不让长时间识图占用一次宿主调用。
状态为 `running | success | failed`。方案保存实际服务商、模型、输入图片、
用户要求、张数、时间和错误，成功后包含：

```ts
interface SceneView {
  id: string
  label: string
  prompt: string
}

interface ScenePlanResult {
  product: string
  material: string
  observations: string
  uncertainties: string
  presetId: string
  reason: string
  prompt: string
  views: SceneView[]
}
```

外部响应必须通过字段、长度、预设 ID、视角数量和唯一性校验。
无效 JSON、未知场景、重复视角或缺少必需字段均失败，不用固定模板假装识图成功。
读取失败可重试读取；重新识图需要用户再次明确操作。

### 使用方案生成

在已有 `image.generate` 中添加可选字段：

```ts
{
  scenePlan: {
    id: string
    prompt: string
    views: SceneView[]
  }
}
```

`scenePlan.prompt/views` 是确认后的编辑稿，顶层 `prompt` 保留用户附加要求，
顶层 `presetId` 是最终选定的场景。
选择自由提示词时保留显式的 `presetId: null`，不恢复推荐预设；
有效的公共场景提示词可以独立使用，顶层附加要求允许为空。
必须使用已经完成的方案、`mode: 'edit'`，并包含原识图图片；
`count` 与提交的视角数一致，每个视角对应原方案中的稳定 ID。
不能同时提交旧的 `visionProviderId/visionFileId`，避免重复识图和含混的执行顺序。
商品来源继续通过 `source` 保存，不向模型发送来源标识、链接等元数据。

## 记录与恢复

生成记录增加可选 `scenePlan`，包含原方案快照、编辑后的公共提示词和视角记录。
每个视角保存标签、编辑稿、最终请求提示词、状态、输出文件 ID 和错误。
旧记录没有此字段时继续走原有流程，不推断或补造智能方案。
列表只返回预览与逐视角状态，详情按 ID 读取完整记录，避免多份长提示词让分页响应
超过宿主消息上限。列表预览不会反向写回存储，也不会用于替代重试的原提示词。

多视角串行执行，每完成一张就保存结果。某张失败继续处理其他视角，
整体记录会反映未全部完成的状态，同时允许查看与导出已经生成的图片。
手动重试沿用原模型、参考图和最终提示词，只执行失败或中断的视角；
已成功视角不会重复计费生成。服务商的端点与 Key 仍读取当前配置，
以便修复凭据，模型和提示词不随配置编辑而改变。

插件重启后不自动发送模型请求。中断任务标记为失败并保留已有成片，
用户可以明确重试。数据写入失败不能显示已保存或已完成；
运行中的任务和仍被记录引用的图片不能因清理旧记录而被删除。
方案按 120 条回收旧数据，仍执行中的方案保留；生成记录另存完整方案快照，
不会因为原方案被回收而丢失历史或影响原任务重试。

## 验证边界

自动化验证使用合成图片和受控模型响应，检查真实插件的请求参数、
状态转换、持久化、部分失败、原选择重试及旧数据兼容。
页面验证覆盖方案生成、编辑、切换输入、模型配置恢复和记录详情。
这些检查不代表任意模型的识图准确率或生成质量，也不代表完成了真实付费接口测试。
实际命令与结果记录于[质量与验证](09-quality-and-testing.md)。
