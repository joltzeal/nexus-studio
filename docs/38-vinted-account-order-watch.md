# Vinted 账号订单查询与 Bark 提醒

账号池插件 `studio.vinted-accounts` 的 `1.1.0` 新增自动订单查询，已独立发布至插件商店。
「订单查询」及 Bark 设置面板随主程序 `0.1.24` 提供；仅更新插件不会给旧主程序增加页面入口。
这里的“订单查询”沿用参考项目的出单监控方式：完整扫描公开衣柜、发现消失商品、
读取商品详情并确认已售，不是登录后的交易订单、买家、付款或物流接口。
已有账号和浏览器窗口的关联规则保持不变，也不需要打开浏览器窗口。

## 使用入口

进入「插件中心 → Vinted 账号 → 订单查询」。
插件启动后自动纳入已有有效 Vinted 用户主页的账号，新建、编辑、表格导入和窗口归档导入
同样维护查询记录。只接受已知 Vinted 站点的 `/member/<数字 ID>` 用户主页。
填写了无效地址的账号显示错误，不对该地址发起后台请求；空主页账号不参与查询。

默认每 30 分钟查询一次，可在面板保存 5–1440 分钟的间隔。
面板提供账号查询状态、最近完整商品数量、最近错误、候选商品，以及暂停、恢复和立即查询。
暂停会保存在插件业务文档中；关闭面板或离开账号页不停止后台任务。
关闭主应用、禁用插件或宿主关闭插件输入流会停止调度并取消请求。
这不是系统服务，主应用退出后不继续查询，也不承诺电脑休眠期间执行。

首次**完整**扫描只建立基线，不推送历史商品。后续完整扫描缺少的商品成为“待核查”，
商品页出现参考实现的 `web_ui__Cell__success` 区域且可见文字为 `Sold` 才确认为已售。
普通文案、脚本、样式、模板或隐藏区域里的相同单词不作为证据。
页面删除、404、拒绝访问、限流及网络错误都不能确认为已售。
核查强制请求英文页面；没有识别到这个标记时保留待核查状态，不猜测交易结果。

商品重新出现在衣柜时关闭本次消失周期；以后再次消失、重新确认已售，可以产生新提醒。
页面状态只是公开页面证据，不能替代真实交易后台。

## Bark 配置

保存 Bark 服务根地址、设备 Key 和启用状态。默认地址为 `https://api.day.app`，
可换成自建 HTTPS 服务；`localhost`、`127.0.0.1` 和 `::1` 的本机服务可使用 HTTP。
不接受地址中的账户口令、查询参数、片段或路径，也不会跟随推送接口的重定向。
启用推送必须有设备 Key；未启用时查询照常运行，已售结果仍会保存。

「测试推送」读取已经保存的配置，实际向该服务 `POST /push`。
只有 HTTP 成功且 JSON `code: 200` 时才反馈发送成功，不把网关 HTML 或业务拒绝算作成功。
单次推送最多等待 15 秒、读取 16 KiB 响应。
测试请求跟随 RPC 取消、截止时间和插件停止信号中止；已被服务接收的消息不能撤回。

已售提醒包含账号标识、商品标题和商品 URL，分组为「Vinted 订单监控」。
不会发送账号密码、接码链接、浏览器 Cookie 或设备目录。
设备 Key 和查询设置按既有约定**明文**存入插件私有 `vinted-accounts.json`，不使用 Keychain。
输入框默认遮蔽 Key 只是显示处理，不是存储加密。

查询和 Bark 使用宿主注入的 Node 全局 `fetch`，继承应用的直连、系统代理或手动代理设置；
显式代理失败不添加直连回退，也不使用窗口代理、代理池默认代理或 Vinted 商品监控的私有代理。
该插件是受信任 Node 进程，manifest 域名声明不是网络沙箱；自建 Bark 和接码地址由用户配置。

## 调度、数据与失败恢复

账号、主页和查询记录在同一份插件文档里原子写入。
每个查询记录持有主页修订 ID、完整快照、候选商品、暂停状态、下次执行时间与已推送时间。
启动时根据当前账号补齐记录；正常账号写入和归档传输也维护同一关系。
删除账号、清空或更换主页会移除对应旧记录；新主页重新建立基线，
旧主页的迟到扫描、核查和通知结果不能写回新主页记录。

插件每 15 秒检查到期任务，最多同时查询两个账号，每个账号同一时刻只执行一次。
手动操作只入队，不把多分钟的扫描留在一个 IPC 请求中；已经运行或并发已满时返回未入队。
单轮最多执行 15 分钟，衣柜最多 20 页、每页 96 条。
重复分页、损坏商品或分页、错误卖家、扫描上限与中途失败均不替换上次完整基线。
失败按原查询间隔与 5–120 分钟的退避中较长者重试。

每轮最多核查 20 个待核查商品，优先检查最久未核查的记录；
每轮最多尝试推送 20 条未发送的已售记录，发送失败保留错误供以后重试。
已经确认的已售记录在后续衣柜扫描失败时仍可重试通知，不把新的网络故障当作撤销既有证据。
已成功推送的记录在重启后仍去重。
保存操作失败不会反馈已保存，也不会清空之前的基线、设置或推送记录。
推送交付与本地文件写入不是跨服务事务：若服务已经收到了推送，而进程恰好在落盘前退出，
下一次仍可能重复发送，不能承诺端到端恰好一次投递。

保留最近 100 条已结束的候选历史；未解决的候选最多 4000 条，
达到上限时拒绝替换本次基线，保留之前的待办。
容量不足时先缩减已结束历史；若未解决待办仍超限，继续核查和推送已有候选，
待腾出空间后再接受下一份完整基线，避免任务永久卡在容量错误。
列表默认只返回各账号摘要；按账号读取才附带最多 100 条最近候选，
避免把所有账号的商品历史塞进宿主 1 MiB 的单行协议。
摘要将长错误合并为“查询失败，请查看详情”，选中账号后返回完整错误；
无效主页也只在详情回传原地址，避免 2000 条长地址或错误撑破协议上限。

## RPC

所有方法沿用已授予的 `account.pool` 能力。

| 方法                                   | 入参                                                         | 返回                                              |
| -------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------- |
| `vinted.accounts.orders.settings.get`  | `{}`                                                         | 查询间隔与 Bark 设置                              |
| `vinted.accounts.orders.settings.save` | `{ intervalMinutes, bark: { baseUrl, deviceKey, enabled } }` | 已保存设置                                        |
| `vinted.accounts.orders.bark.test`     | `{}`                                                         | `{ sent: true }`，失败抛结构化错误                |
| `vinted.accounts.orders.list`          | `{ accountId? }`                                             | `{ items }`，无 ID 时返回摘要，有 ID 时附最近候选 |
| `vinted.accounts.orders.run`           | `{ accountId }`                                              | `{ queued }`                                      |
| `vinted.accounts.orders.enabled`       | `{ accountId, enabled }`                                     | `{ enabled }`                                     |
| `configuration.export`                 | `{}`                                                         | `{ schemaVersion: 1, data: settings }`            |
| `configuration.validate`               | 版本化配置                                                   | `{ valid: true }`，不写入、不联网                 |
| `configuration.import`                 | 版本化配置                                                   | `{ imported: true }`                              |

设置通过「应用设置 → 配置迁移」导入导出。
只迁移查询间隔和 Bark 配置，不携带账号、衣柜快照、候选商品、暂停记录或推送历史。
窗口加密迁移沿用原有账号与绑定附件，不把源设备的后台任务或推送历史复制成目标设备的已售证据。
导入与直接保存使用同一队列内取消检查；排队期间取消或超过截止时间不写入新配置。

## 代码与验证

参考源码为 `nexus-cart/packages/platform/src/pages/vinted-orders/watch-*`，
以及同项目 `apps/api/backend/app/vinted/orders/watch_service.py`、
`watch_scan.py` 和 `bark_settings.py`；Raccoon 不依赖该项目运行时或数据库。

本项目入口：

- `plugins/vinted-accounts/src/capabilities/order-watch.ts`：调度、RPC、状态转换和去重。
- `plugins/vinted-accounts/src/domain/order-watch.ts`：配置、持久化结构和账号关系。
- `plugins/vinted-accounts/src/services/order-source.ts`：完整衣柜扫描与页面已售证据。
- `plugins/vinted-accounts/src/services/bark.ts`：有界推送与响应校验。
- `apps/desktop/src/features/accounts/order-watch-panel.tsx`：查询结果与配置界面。

使用受控请求响应测试完整基线、重启去重、失败恢复、暂停、导入、主页更换、
停止与通知协议；真实账号和 Bark 设备不作为自动化测试环境。
本地按约定不构建、不打包、不运行 Rust 编译或测试，实际结果见[质量记录](09-quality-and-testing.md)。
