# 应用代理

## 当前实现

设置 → 应用代理支持“不代理”“系统代理”“手动代理”，保存在本机 `nexus.sqlite`。
手动模式接受不含用户名与密码的 `http://`、`https://` 或 `socks5://` 地址，
必须包含端口，例如 `socks5://127.0.0.1:7890`。读取或保存失败会显示错误。
初次安装默认不代理；修改配置后已启动的插件进程被停止并由宿主重新拉起。

Rust 插件商店请求使用显式配置的 reqwest 客户端，不沿用进程环境中的代理变量；
浏览器适配器和插件子进程在启动时注入代理预加载模块，将 Node `fetch` 通过
HTTP(S) 或 SOCKS5 转发。代理连接失败时这些请求报错，不回退到直连。
激活码校验与内核准备也使用此预加载模块。已启动的浏览器适配器不会热切换，
需要关闭该窗口再启动。窗口自身的浏览器代理仍由窗口配置决定，应用代理
不会修改 Profile 的浏览器流量。

## 系统代理边界

macOS 从 `scutil --proxy` 读取 SOCKS、HTTPS 或 HTTP 的静态配置；
Windows 从当前用户的 Internet Settings 读取静态代理。
自动配置脚本 PAC 不受支持；检测到 PAC 时拒绝保存或请求，并提示改用手动代理。
如果系统没有设置代理，系统代理模式按系统现状直连。系统代理改变后，
新启动的子进程使用新配置；插件商店每次请求重新读取。

插件为受信任的独立 Node 进程。当前统一代理覆盖 Node `fetch` 和商店
reqwest；插件自行创建的原始套接字、特定 HTTP 客户端以及浏览器页面流量
不受这一层约束。代理池插件自身的代理连通性检测会连接指定端点，
不能将应用代理当成插件进程的网络沙箱。

## 验证

在桌面设置中保存手动 SOCKS5 地址，刷新插件商店或使用发起 `fetch` 的插件；
停止本机代理后同一请求应报连接错误。用系统代理模式重复检查，
随后切换“不代理”确认请求恢复正常。分别在 macOS 和 Windows 安装包上验证。
