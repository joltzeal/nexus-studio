# 原生 Profile 创建与试用

## 数据边界

窗口管理页的“创建窗口”直接创建原生 Profile，不再并列展示 localStorage 演示窗口。
创建后 Rust 在 Tauri 应用数据目录下创建 UUID 目录，并将配置写入 `nexus.sqlite`；
旧版本的 `profile.json` 会迁入 SQLite。
记录包含名称、内核通道、精确版本、官方包装层返回的二进制路径和可选无凭据代理服务器地址。
目录下 `user-data` 由 CloakBrowser 的持久上下文使用，包含 Cookie 等真实浏览器数据。
页面支持编辑原生配置和删除 Profile（包括浏览器数据）；旧演示窗口数据不自动迁移。
Profile 记录里没有账号字段：Vinted 账号由 `studio.vinted-accounts` 插件保存，
插件只记住 Profile 的 UUID，窗口名称仍只在主程序里。

## 列表顺序与备注

`ProfileStore::list` 先按 SQLite `rowid DESC` 读取，再按 `created_at` 稳定倒序排列，
保证同一秒创建的记录仍按后创建优先；刷新或重启不会改成随机 UUID 顺序。
前端沿用此顺序，按创建时间作稳定排序，并将创建命令返回的新记录放在前端列表头部。
修改备注与记录最近打开时间均使用 `UPDATE`，不会改变插入顺序。
旧版缺失创建时间的记录按 0 排到最后；不根据名称或最近打开时间猜测创建时间。

`profile_update_note(id, note)` 是独立的元数据写入口，最多 120 个 Unicode 字符，
去除首尾空白，空字符串用于清除备注。SQLite 用 `json_set` 只改 `settings.note`，
不使用前端的整条记录覆盖当前代理、分组、指纹、内核绑定和最近打开时间。
成功返回保存后的备注；前端收到确认后才更新对应行，失败保留草稿。
行内编辑失焦、Enter 或保存按钮共用同一入口，保存期间阻止重复写入；
Esc 和取消按钮不落盘。输入与显示保持相同行高，失败使用提示反馈而不扩张表格行。
此命令允许窗口运行时调用；同一窗口迁移、资料恢复或应用更新安装期间拒绝写入。
完整浏览器配置编辑仍要求先停止窗口。

## 创建与启动

从仓库根目录执行 `rtk proxy pnpm run desktop:dev`，已有 Nexus 前端预览服务
占用 1420 时会复用它。进入“窗口管理”，
先在设置保存激活码，再在“创建窗口”填写名称和浏览器配置，
并选择直连、HTTP/SOCKS5 手动代理或代理插件。
代理只允许不含账号密码的 `协议://主机:端口`，首次准备可能需要下载浏览器。
创建成功后列表显示实际内核版本；点击“打开”启动可见浏览器，
点击“停止”关闭。浏览器预览页无法调用原生后端。
窗口管理也支持「批量创建」，Vinted 账号池支持选中多个账号各创建并关联一个窗口。
两处复用完整配置表单，统一设置代理和浏览器配置，每个窗口独立随机种子；
逐项执行、部分失败重试和停止规则见[批量创建窗口](32-batch-window-creation.md)。
首次创建可能需要下载内核，创建按钮会显示“正在准备内核”；
准备失败或超过 12 分钟会反馈错误且保留表单输入。创建命令返回已保存窗口，
界面直接加入列表，不再等待额外的列表刷新才结束保存状态。

新建窗口默认使用最新稳定内核，也可选择本机清单中的完整包版本；
需要其他版本时先到「应用设置 → 浏览器内核」下载指定版本，再刷新选择器。
清单读取失败保留当前选择并允许重试，不阻止默认最新版本创建；
激活码未配置时提示前往设置并禁用创建。
Rust 在启动适配器前再次检查激活码，Node 在调用 SDK 前拒绝空密钥。
`profile_create` 接受可选 `kernelVersion`，精确选择优先复用已安装包，
缺失时尝试获取该完整包；版本或修订不符时拒绝创建。
返回值同时包含 Chrome 显示 `version` 和绑定目录中的完整 `kernelVersion`。
下载结果和启动路径只接受受管新版缓存；旧公开内核窗口不兼容，需要重新创建，
程序不自动重绑或删除旧目录。本应用不会创建额外账号或修改许可。
创建后列表显示实际版本，不会自动升级已有 Profile。
编辑窗口不展示内核选择器，`profile_update` 不接收版本参数。
启动前核对二进制 `--version` 与创建时的版本，若文件被更新、删除或替换则报错。
同一 Profile 不允许改用另一个版本；需要新内核时新建 Profile。
多个独立 Profile 可同时启动；相同 Profile 在启动、运行或停止期间不能重复启动。
Nexus 不硬编码一个会话的限制，CloakBrowser 根据当前密钥和计划裁决实际并发席位；
席位不足时启动失败并显示适配进程返回的错误，不自动换内核或回退直连。
窗口页展示本应用中已运行的 Profile 数量，不将它表述为许可席位数。

## 失败与恢复

目录已存在但 `profile.json` 缺失、损坏或绑定字段不一致时会报错，不自动重建。
新应用实例从磁盘读取绑定；正在运行的浏览器进程不会自动重连。
创建失败不应显示为创建成功；启动失败保留绑定以便排查，不转换为直连或别的版本。
手动关闭浏览器后列表刷新会回收运行状态。
窗口页支持选中窗口后加密导出、导入副本或显式覆盖，并通过窗口同步插件传到另一台设备。
导出前需要停止窗口；迁移期间不能启动、编辑或删除同一窗口。
导入保留精确内核版本、指纹种子和插件关联，不静默升级已有窗口。
迁移包另外记录本机清单中的完整内核包修订号；
Chrome 显示版本相同但 SDK 包修订不同，不能视为同一个环境内核。
Cookie 与站点存储通过浏览器接口额外导出，解决仅复制数据库无法跨设备使用的问题。
迁移格式、事务与兼容边界见[窗口加密迁移](28-window-transfer.md)；
设备配对与网络边界见[窗口同步插件](29-window-sync-plugin.md)。
删除操作仍会永久删除该窗口目录。

## 分发边界

开发模式使用仓库运行时与本机 Node.js；正式发行流程随应用分发受管 Node 与 JS 依赖。
本次重构只执行不产生构建产物的本地检查，Rust 编译与测试交给 CI；仍需分别验证
macOS/Windows 安装包的路径、退出清理与激活行为。CloakBrowser JS wrapper 为 MIT 授权，官方二进制另有许可，
不得将本阶段的开发启动视为可对外分发的成品。
