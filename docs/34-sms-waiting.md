# 窗口行短信验证码等待

本功能属于 Nexus 主应用 `0.1.17`，入口位于窗口管理表格中已关联账号的手机号旁。
账号资料与窗口绑定沿用 [Vinted 账号池插件](24-vinted-accounts-plugin.md)；
号码来源可以是 [SIM8 号码池](30-sim8-plugin.md)，也可以是手动保存的资料。
等待只读取账号已保存的短信接码链接，不要求 SIM8 插件正在运行。

实现复用 `account.pool` 的 `vinted.accounts.list` 和 `vinted.accounts.otp`，
没有新增插件 RPC、能力声明或存储字段，也不提升账号插件版本。
行按钮与等待调度由主应用提供，单独升级插件不会给旧版主应用增加入口。

## 使用入口与结果

窗口已关联账号、账号已保存非空手机号和短信接码链接，且桌面账号插件与账号资料
就绪时，可以点击「等待验证码」。没有手机号时不显示按钮；缺少接码链接时禁用
启动并提示先保存链接。插件或资料未就绪、手机号正在解绑时不能开始新的等待。
打开页面、展开短信弹层、保存资料或切换页面都不会自动开始等待。

点击后按钮显示「等待中」和加载图标；再次点击停止当前账号的等待。
停止、收到验证码或满 5 分钟后都回到可手动开始的状态，不自动续期或重新启动。
短信弹层原有的「读取短信验证码」仍是独立的单次读取操作。

收到有效验证码后，当前等待先结束，再显示包含发起窗口名称、账号、手机号和
验证码的成功提示，提供「复制验证码」操作，并尝试播放一次提示音。
复制成功或失败分别反馈；复制失败时可以从提示中手动复制。
成功提示没有自动消失计时，可以手动关闭。

全局提示区最多同时显示 3 条提示。超出的常驻提示进入等待队列，并显示待展示数量；
关闭可见提示后补入队列中的提示。多个账号同时收到验证码时，常驻结果不会因为
超过可见数量而被丢弃。提示和队列仅属于本次应用会话，不是持久验证码历史。

## 查询节奏、截止时间与重试

| 情况                             | 行为                                                          |
| -------------------------------- | ------------------------------------------------------------- |
| 手动开始                         | 立即尝试第一轮读取，同时以本次开始时间设定 5 分钟截止时间     |
| 正常等待                         | 从开始时起每 5 秒触发一个查询时点                             |
| 同账号上一轮仍未结束             | 跳过该时点，不并发查询、不积压待补发的读取                    |
| 返回 `code: null`                | 继续等待；清除先前保留的查询错误                              |
| 查询失败或响应不合法             | 保留最近一次错误，在后续时点重试，不延长截止时间              |
| 收到 4 位或 6 位纯数字短信验证码 | 本轮只通知一次，然后停止等待                                  |
| 达到 5 分钟                      | 停止任务，不额外发起最后一轮读取，显示超时提示                |
| 停止后手动重开                   | 建立新的 5 分钟任务；同账号旧读取未结束时，仍需等待其释放占用 |

一次读取按顺序执行账号清单校验、短信取码、再次读取账号清单校验。
这里的「每 5 秒」是调度时点，不是每个 HTTP 请求的超时，也不是上一轮完成后再等
5 秒。慢请求期间的时点直接跳过，不同账号可以独立等待。
停止后立即重开也不会绕过同账号占用：旧读取结束后，新任务在后续可用时点读取。

运行时只接受 `channel: 'sms'` 的结果；其他渠道或非 4/6 位数字验证码按失败处理。
查询错误显示在等待按钮的提示文字中，并说明会继续重试，不为每次失败反复弹出
通知。到期时若仍保留错误，超时提示附带最近一次查询错误；正常的无验证码响应
会清掉该错误。插件不可用或目标资料失效属于停止条件，不按普通查询失败无限重试。

截止时间使用实际经过的墙钟时间。页面或系统暂停可能延后定时器回调，但恢复后
接受查询结果前仍检查是否过期；已经超过 5 分钟的结果不会触发成功通知。
重试、页面导航和慢请求都不会延长本次等待，继续等待需要用户重新点击。

## 共享账号、页面导航与停止范围

任务以账号 ID 去重。同一账号关联多个窗口时，只创建一个等待任务，各行共享
「等待中」状态；连续重复点击不会启动第二条任务。
任一共享账号行上的手动停止都会结束该账号的等待。
成功通知使用本次任务开始时记录的发起窗口名称、账号名称和手机号。

自动停止按变更对象区分范围：

| 变更                                                   | 停止范围                             |
| ------------------------------------------------------ | ------------------------------------ |
| 开始解绑手机号                                         | 停止该账号的等待，影响所有共享行     |
| 成功保存后手机号或短信接码链接改变                     | 停止该账号的等待，不能继续使用旧资料 |
| 发起等待的窗口解除或更换账号关联、确认删除             | 停止由这个窗口发起的等待             |
| 同账号的其他窗口解除或更换关联、确认删除               | 保留由原窗口发起的等待               |
| 查询校验发现账号已删除、联系资料改变或发起窗口绑定失效 | 停止该任务并说明资料或关联已变化     |
| 账号插件不可用、被替换或重启                           | 停止全部账号等待，并提示插件状态变化 |

窗口页对解绑手机号、发起窗口的改绑/解绑和确认删除，在发起操作时即停止相应
等待；即使后续写入失败，也不会自动恢复已停止的任务。
普通资料编辑则在保存成功并发现手机号或接码链接变化时停止。
其他页面或外部操作引起的资料变化，在查询前后的清单校验中确认。
账号名称或窗口名称不是短信链接匹配条件，通知名称取自开始时的记录。

等待管理器属于应用级运行时，不随窗口表格行或窗口页面卸载而销毁。
在应用内导航到其他页面、筛选或隐藏相关行，不会停止已启动的等待；
返回窗口页后重新订阅同一任务状态。应用壳持续观察账号插件目录：
插件缺失、禁用、非运行状态，或版本/PID 身份变化时，停止已有任务。

应用壳卸载时清理全部任务和提示音资源。任务、截止时间、最近查询错误以及音频
上下文都不写入 localStorage、SQLite 或插件存储；刷新 WebView 或重启应用后
不会恢复等待。已保存的账号、手机号和接码链接继续由原有账号存储管理。

## 资料校验、取消信号与迟到结果

开始时记录账号 ID、发起窗口 ID、手机号和短信接码链接。
每轮先通过 `vinted.accounts.list` 检查账号仍存在、手机号与链接和开始时完全
一致，并确认发起窗口仍绑定这个账号；不满足时不发起短信读取。
取码调用为 `vinted.accounts.otp({ accountId, channel: 'sms' })`，
插件读取自己保存的链接。收到响应后再读取一次清单，用相同条件确认结果仍适用。
任一侧校验失败都会停止，不把等待悄悄转移到新号码、新链接或新账号。

每个任务有自己的 `AbortSignal`。停止、到期或应用清理会中止该信号；
运行时在每个已等待的调用返回后检查信号，避免继续发起下一步调用。
管理器还检查任务身份和截止时间，使旧任务的成功或失败不能覆盖手动重开的任务，
也不能再次通知或播放提示音。

**这里没有原生 IPC 取消能力。** `listAccounts()`、`readOtp()` 与宿主
`plugin_call` 没有接收本任务的取消信号。已经发出的 IPC 或插件网络请求可能继续
执行，停止表示终止前端后续调度并忽略迟到结果，不表示请求已被远端撤回。
同账号的读取占用保留到旧读取实际结束，防止停止后重开造成请求重叠。

## 提示音与短信时间边界

用户点击开始时同步调用 `VerificationSound.arm()` 创建或恢复 Web Audio
上下文，再开始网络查询；不等待音频准备完成，也不在开始等待时播放声音。
收到验证码后调用一次 `play()`，由 Web Audio 合成短促的双音提示，
不下载音频、不引入音频依赖，也不发送操作系统通知。

音频不受支持、播放受阻、恢复失败或恢复等待超过 1 秒时返回失败。
运行时保留验证码成功提示，另行说明提示音未能播放；音频失败不会重启取码任务。
音频上下文可供多个等待任务复用，播放结束会断开节点；上下文暂停、关闭、
部分调度失败或应用清理时也释放相应资源。关闭操作可重复调用，后续用户点击
可以重新准备音频。

`play()` 返回成功只说明音频节点已调度，**不保证操作系统扬声器实际发声**；
系统静音、音量、输出设备或 WebView 播放限制都可能影响实际可听性。
没有声音时仍可从文字提示读取、复制验证码。

**本功能不保证验证码来自本次等待开始之后的新短信。**
既有 OTP 响应的 `fetchedAt` 是查询完成时间，不是短信发送或到达时间；
等待逻辑没有可靠的短信时间戳、首轮旧码基线或跨任务去重。
上游若一直返回旧验证码，首次读取或手动重开后都可能再次显示同一验证码。
收到结果只代表现有接口提取出有效格式的数字，不证明验证码尚未过期或可用于登录。
本功能不发送短信、不登录账号，也不自动填入浏览器。
