# 产品定位与范围

## 当前阶段

Nexus 是面向 macOS / Windows 的多环境管理桌面产品，当前采用现代、克制的 B 端后台风格。
桌面窗口页直接创建磁盘持久的原生 Profile，可配置、启动、停止和删除。
SQLite 当前只保存 CloakBrowser 授权密钥；窗口 Profile 使用独立目录，业务数据迁移后续接入。
本次调整取代此前“桌面 Rust SQLite 偏好已作为基础能力交付”的范围描述。
完整产品架构仍保留为长期规划，不能将规划描述成当前可用能力。
页面是否实现和检查是否通过，以主线代码与[验证记录](09-quality-and-testing.md)为准。

## 九个主页面

| 页面        | 当前演示内容                               | 能力边界                                                                 |
| ----------- | ------------------------------------------ | ------------------------------------------------------------------------ |
| 窗口管理    | shadcn Table、搜索、配置增删改查和启停     | 桌面创建真实 Profile；网页预览只读                                       |
| 分组管理    | 原生分组的未接入状态                       | 旧本地分组不属于真实窗口                                                 |

| 代理池      | 库存、检测、订阅、默认代理与凭据槽         | 依赖插件宿主；未验证真实出口流量                                         |
| 地址生成器  | 公开地址生成、地图选点、复制与 CSV 导出    | 依赖插件宿主与 Overpass；不做收件验证                                    |
| 共享货源    | 分类商户、商品搜索、以图搜图与本地收藏     | 依赖插件宿主与第三方目录接口；不保证可下单                               |
| AI 生图     | 生成记录、生图改图、文案与滑动对比         | 依赖插件宿主与外部生图接口；明文密钥存插件私有目录                       |

窗口详情与插件状态需要就近表达未接入或失败原因，不能只在文档中解释。

## 当前工程边界

- 前端采用 React、TypeScript、Vite、Tailwind 4 与 shadcn/ui。
- Tauri 承载原生 Profile、SQLite 授权与插件宿主命令，其他业务数据尚未迁入 SQLite。
- localStorage 保存旧分组和外观/工作区偏好，不作为真实窗口的数据源。
- contracts、plugin-sdk 与 browser-runtime 保留独立包边界。
- browser-runtime 的纯 TypeScript 健康协议不接入页面，也不启动浏览器。
- 不接入 Manager、Python、FastAPI、Docker 或电商业务服务。

桌面 WebView 与浏览器预览各自使用当前来源的 localStorage，不自动共享数据。
偏好保存不是数据库写入；窗口的 Profile 目录则在应用数据目录持久化。
插件在桌面应用中由宿主进程真实执行；浏览器窗口必须显式点击“打开”才启动。

## 后台交互结构

左侧展示 Nexus 标识、当前工作区和八个紧凑导航入口。
轻量顶栏展示面包屑、实际提供的快捷操作。
主体以环境列表与工具栏为中心，分组使用简洁卡片，插件使用克制的能力卡。
后台风格不意味着本轮增加企业权限、多租户或其他服务端业务。
窗口管理、分组管理、插件中心、代理池、地址生成器、共享货源、AI 生图、Vinted 监控、应用设置保持同级入口，设置内部再区分四个子页面。
空状态、禁用状态和存储错误都应说明实际情况，不能编造在线或成功状态。
插件启用只表示宿主已授权并启动其进程，不能出现“已连接真实引擎”等反馈。
键盘、焦点、长文本、窗口缩放与窄屏预览纳入页面质量要求。

## 最新视觉方向

保留纸白与钴蓝，具体 token 和组件状态以[主题规范](04-theme.md)为准。
采用紧凑排版、稳定对齐、轻分隔与适度圆角，避免古典后台的厚重装饰。
去掉夸张大标题、插画、层叠窗口主视觉与营销式留白。
此前无侧栏、无表格的限制已取消，列表和工具栏服务于实际操作。
主题值与组件变体集中维护，页面使用语义 token，不在 JSX 散落原始色值。

## 长期完整产品规划

Rust 核心已是授权 SQLite 的唯一所有者，并监督 Node.js 浏览器适配进程；业务表尚未接入。
真实浏览器采用不可变启动配置快照与 profile 独占锁。
要求代理时失败必须阻断，禁止自动回退直连，具体 SDK 行为需集成验证。
当前真实插件采用受信任 TypeScript 进程；manifest 和权限声明不是沙箱。
业务库只存密钥引用；插件密码由插件明文保存在自己的私有目录。
最终安装体验目标不要求用户配置 Node、Rust、Python、PATH 或 `.env`。
上述规划分别见[架构](02-architecture.md)、[浏览器](05-browser-integration.md)与[分发](08-distribution.md)。
