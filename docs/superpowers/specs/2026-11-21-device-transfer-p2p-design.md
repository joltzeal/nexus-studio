# Raccoon 设备传输：完整环境副本与公网 P2P

日期：2026-11-21。状态：公网 P2P、公共 STUN、完整 Profile 配置及浏览器站点数据已确认；缺失插件的延后恢复规则为本轮建议。本文不表示新传输能力已实现。

## 1. 已确认的目标

- 将设备 A 选中的完整 Profile 环境和关联数据复制一份到设备 B，不仅复制空白配置。
- 浏览器持久化资料属于必需范围，包括 Cookies、localStorage、IndexedDB、OPFS 等站点数据；不能将保留登录态从首版移除。
- 两台设备都运行 Raccoon；不依赖同一局域网，不建设云端业务服务或文件存储。
- 使用 P2P，允许公共 STUN 辅助连接发现。
- 操作由用户手动开始，B 预览后明确导入。
- 重做窗口同步插件，保留现有用户数据，不提供旧 TCP 邀请的运行时兼容。
- desktop-v2 沿用现有 ShardX UI Kit、主题和页面组织方式。

这是一项跨主程序与插件的功能。插件负责连接和传输，Rust 与各业务插件分别负责自身数据的导出、校验与写入。

## 2. 本文提出的首版取舍

以下是实现建议，不作为用户此前已经逐项确认的需求：

- 显示名称改为「设备传输」，保留安装身份 `studio.window-sync`，避免产生两个插件条目。
- 首版复制完整 Profile、持久浏览器资料和用户选中的业务记录。浏览器内核按原版本在目标平台安装及核对，不直接复制原设备的可执行文件。
- 不建设信令服务器；通过双方手工交换完整邀请和应答传递连接信息。
- 不配置 TURN，也不自动转发业务包；直连失败时使用同一加密包的文件导入出口。
- 首次导入创建独立副本。已有资料默认保留，重复项先预览，不按更新时间静默覆盖。
- 完整 Profile 必需的站点凭据随环境纳入加密包；所选业务资料需要的账号密码、Token 和 API Key 在预览中明确标注类别，不展示原值。用户可以明确排除某项业务资料，但不能剥离必要凭据后将该项标为完整恢复。
- B 缺少业务插件时保留加密资料和导入任务，先恢复依赖已满足的部分；安装兼容插件后明确继续恢复，不静默丢弃资料，也不由迁移包自动安装插件代码。

本文确认后再写实施计划和修改产品代码。已有导出文件与用户业务数据不因协议替换而删除。

## 3. 现有实现与可复用部分

`plugins/window-sync` 当前提供 `sync.offer/receive/status/cancel`，使用 TCP 直连邀请中给定的主机和端口。
它只运输主程序生成的不透明加密归档；没有 ICE、STUN、信令交换或 NAT 打洞。
原生宿主通过窗口迁移专用命令管理文件路径，通用 WebView `plugin_call` 不开放 `sync.*`。

`core/transfer_service.rs` 的现有整窗归档有 CloakBrowser、已停止窗口和精确内核版本等约束，不能直接当成任意 Provider 的完整环境复制。
`configuration.export/validate/import` 当前主要是设置迁移；邮箱账号、号码、商品等业务库存不因此自动成为可迁移数据。
现有 `snapshot` / `portable-state` 路径读取并恢复 Cookies、localStorage、IndexedDB 和 OPFS，同时携带经过校验的用户资料目录；这只是可复用基础，不代表所有 Provider 或跨平台登录恢复已验证。

可复用的基础包括归档认证加密、路径校验、原生临时目录管理、插件权限门禁、接收落盘回执和导入操作日志。
新的设备副本格式单独版本化，不改变旧整窗文件的解释。旧整窗导入遇到缺失插件仍会拒绝；本文的延后恢复需要新的原生协调与日志，不能仅修改提示文案冒充已支持。

## 4. 方案比较与选定方向

| 方案                          | 需要的服务           | 本轮结论                             |
| ----------------------------- | -------------------- | ------------------------------------ |
| 现有 TCP 地址直连             | 可达地址或已配置路由 | 无法满足一般异地网络，替换其连接方式 |
| ICE/STUN + 手工交换邀请和应答 | 公共 STUN            | 选定方向；配置包由设备直接互传       |
| 信令服务 + ICE/TURN           | 新信令及可选中继     | 本轮不做，不以短数字码伪装成无需服务 |

公共 STUN 服务参与公网映射发现，可以看到请求来源及网络元数据；它不接收迁移包。
公网直连不能保证在所有 NAT、防火墙或网络策略下成功。两端必须同时在线，发送方需保持应用打开。

## 5. 用户流程

### A：发送

1. 进入「设备传输 → 发送」，选中需要复制的完整 Profile 与插件资料。
2. 关闭所选 Profile，预览站点资料、关联依赖、凭据范围、快照大小和不支持的项目；锁定快照期间的启动、编辑与删除。
3. 设置迁移包密码。Rust 与业务插件生成冻结的加密包；生成失败不进入传输。
4. 创建 P2P 会话，完成本地 ICE 候选收集后显示完整邀请文本，提供复制。
5. 等待 B 返回应答，粘贴并确认后尝试建立直连。
6. 连接后显示双方核对码，用户确认一致后开始发送。
7. 收到接收落盘及散列校验回执后显示「对方已接收」，不推断 B 已导入。

### B：接收

1. 进入「设备传输 → 接收」，粘贴 A 的邀请并开始候选收集。
2. 生成完整应答文本，复制给 A；无需登录或查询中心服务器。
3. 连接后核对双方核对码，确认后接收。
4. 接收包完整落盘并校验后显示「已接收，等待导入」。
5. 输入包密码，Rust 解密、验证，再显示新增、重复、内核及 Provider 兼容性、缺失插件、缺失依赖与目标 Workspace 映射。
6. 明确导入，逐项显示已恢复、等待安装插件、等待依赖、失败和待核对结果。完整环境恢复要求配置与站点资料均通过校验，不以接收包完成代替恢复完成。
7. 缺少插件时保留原始加密包，在同一任务中进入插件中心安装；返回后重新检查兼容性，由用户点击「继续恢复」。重启后仍可继续，需重新输入包密码。

顶层使用现有页面 Card 与发送/接收工具切换。邀请和应答使用多行只读或输入控件，进度使用实际传输字节。
不把完整连接描述包装成六位数字码；不默认使用二维码承载可能很长的连接描述。
连接失败可以重建新会话，或在 A 保存冻结的加密包，再由 B 从文件打开并进入同一导入流程。

## 6. 数据范围与导入语义

| 分类         | 首版设计                                                    | 明确排除                                             |
| ------------ | ----------------------------------------------------------- | ---------------------------------------------------- |
| Profile      | 完整可迁移配置、指纹、Folder/标签、代理引用及持久浏览器资料 | 本机二进制路径、运行状态、进程锁、原设备厂商连接密钥 |
| 主程序代理   | 所选代理条目及被选中 Profile 依赖的代理                     | 检测任务、实时连通性结论                             |
| 插件设置     | 插件明确声明可导出的设置                                    | 未声明的私有目录、安装代码、设备授权租约             |
| 插件业务记录 | 通过新版本化副本接口导出的所选记录及依赖                    | 运行中任务、自动购买/发布操作、历史任务自动重放      |
| 凭据         | 双方均能在清单中确认的显式选中字段                          | 隐藏夹带、不经确认恢复自动执行                       |

### 6.1 完整 Profile 与站点数据

完整环境包含 Profile 的浏览器配置和对应持久用户资料：Cookies、localStorage、IndexedDB、OPFS、站点权限，以及 Provider 支持快照的书签、历史、扩展配置与扩展存储、Service Worker / CacheStorage 等。按数据类别列出覆盖情况，不能仅导出 Cookies 就标为「完整环境」。用户资料所需的二进制附件独立流式携带，不塞进配置 JSON。

导出前必须停止 Profile，持有原生操作锁并生成一致的冻结快照。用于读取便携状态的临时浏览器受控运行，不执行业务插件任务或对目标网站重放操作；生成失败则整项失败，不发送缺失站点资料的空壳。

浏览器 API 可移植状态与安全校验后的用户资料快照共同构成恢复输入；涉及设备绑定的资料须由对应 Provider 的导出/恢复机制处理，不能把复制原始 Cookie 数据库视为跨设备恢复完成。对仅存在于运行中标签页内存、无法落盘或导出的会话资料，不承诺停止后仍存在；必须在预览中说明实际不支持的数据类别，不能声称复制了进程内存。

目标恢复要求 Provider 类型、浏览器家族、精确内核包及数据格式兼容。macOS / Windows 使用各平台对应内核，验证可移植状态恢复；不能把 Chromium 目录导入 Firefox，也不能仅凭显示版本相同跳过内核包核对。指纹配置与种子保留，跨操作系统的差异明确展示。

每个 Provider 分别声明并实现完整快照能力；当前 CloakBrowser 路径可以复用和补齐，其他 Provider 必须接入受支持的官方导出/恢复能力。缺少能力时该 Profile 显示「暂不支持完整环境迁移」并阻止整项导出/导入，不读取厂商私有目录，不降级为空白 Profile。用户要求是完整数据；不支持是待完成项，不能以配置复制替代验收。

进程锁、运行中 socket、原机绝对路径、可执行内核和不属于所选 Profile 的文件不按业务资料直接复制；被引用的本机文件需预览并明确重映射或报告缺失。完整快照记录站点资料的覆盖清单及完整性摘要，恢复后校验；远端网站是否继续承认会话仍由网站决定，不能将其保证为永不失效的登录。

### 6.2 原生与业务关系

不直接复制整个 SQLite，不让同步插件读取其他插件的 JSON 文件。
业务记录支持按插件逐个接入；尚无副本接口的插件标注「暂不支持业务资料复制」，不能只导出设置却反馈账号也已复制。

Profile 通过目标 Provider 的完整环境恢复契约建立独立副本，生成新的 Raccoon UUID，并记录源 UUID 到目标 UUID 的映射；仅调用创建空白 Profile 的契约不满足要求。
接收端选择并探测目标 `connectionId`，Folder 与标签按该连接落地，禁止仅凭 `providerId` 合并 Workspace。
厂商环境 ID、接入绑定和原机路径不直接导入；目标不支持相应字段或创建能力时，该项明确阻断。
站点资料恢复完成前，该 Profile 不显示完整恢复成功，也不开放正常启动。完整环境复制不等于将源设备的 AdsPower/比特环境 ID 接管到另一台机器。

插件副本协议必须返回本地 ID 映射，供邮箱、Vinted 账号、代理池端点和地址等关系重建。
无法完整导出依赖时，导出预览阻止选中该关系；接收端暂时缺少插件时按第 6.3 节延后恢复，不得悬空写入运行态关联后显示整组成功。
疑似重复记录先展示；用户选择复用已存在记录时，插件重新核对目标身份并提供映射。默认不自动绑定同名或同邮箱记录。

导入新实例时，自动收信、监控、定时刷新与 Agent 等自动执行开关先保持关闭，由用户在目标设备上开启。
不会因为复制任务记录而在 B 重放业务操作。

### 6.3 B 未安装业务插件：保留待恢复

推荐默认行为是「能恢复的先恢复，缺少插件的加密保留，安装后继续」。不强迫 B 预装全部业务插件，也不静默跳过后删除数据。

- 归档分开存放原生 Profile 快照、每个插件的数据节和关系清单。清单包含稳定插件 ID、导出插件版本、数据 schema、恢复能力要求及源记录引用，不携带插件程序、安装脚本或设备授权租约。
- 预检按「可恢复」「未安装」「版本/数据格式不兼容」「授权未就绪」「缺少依赖」分别列出插件及受影响数量，提供现有插件中心入口。只凭相同插件 ID 或版本更高不能判定兼容，必须验证恢复接口与数据 schema；不自动降级或执行未知迁移器。
- 缺少插件的数据节由 Rust 作为不透明归档保留，不让其他插件接管，不写进未安装插件的私有目录。仅持久化原始加密包及导入日志；解密临时资料按本次预检/恢复生命周期清理，密码不落盘。安装后重新输入密码，再把该插件获准的数据节交给已安装插件验证。
- 插件只能从用户信任的既有插件中心或本地安装入口安装，沿用真实的包校验、权限与授权门禁。数据包不能指定任意下载 URL 或自动安装代码；A 的插件授权不复制给 B。离线或暂时无法获取插件时，任务保持待恢复。
- 同一导入任务持久化已确认的 Profile/插件记录 ID 映射与逐项收据。安装完成只触发重新检查，不自动写入业务数据；点击「继续恢复」后仅处理未完成项，不重复创建已导入的 Profile 或账号。重启继续同一任务也使用稳定操作 ID；目标记录已被删除或更换时重新预检，不复用失效映射。
- 跨插件关系形成有依赖顺序的数据组。例如有邮箱关联的 Vinted 账号在邮箱插件缺失时，其依赖组保持等待；其他无关资料可以恢复。关系两端及 ID 映射均确认后再建立关联，不把 A 的数字 ID 直接写入 B，不按同名或同邮箱自动匹配。
- Profile 的浏览器快照可独立于可选业务插件恢复；邮箱、商品等可选关系继续保留在待恢复任务中。若缺少的是 Profile 的必需运行依赖，例如代理池插件或具体代理端点，则记录依赖阻断，禁止启动且绝不回退直连；安装恢复完成或用户明确改绑有效代理后才解除。
- 接收页展示「Profile 已恢复；邮箱资料待安装插件」等分项结果，整体状态保持部分完成。只有所有所选数据及关系均完成才显示全部完成；用户可以明确放弃待恢复项，界面保留其未恢复的事实。
- 原始加密包在全部恢复前由应用保留，支持导出备份与显式删除，不因退出、关闭页面、P2P 会话结束或普通缓存清理而消失。磁盘预检计入保留包与解密工作空间；空间不足先阻止接收/恢复，清理需用户明确选择，不能静默淘汰仍待恢复的数据。

「设备传输」插件本身是 P2P 会话两端的前提，不能通过尚未建立的传输来安装自己；B 未安装时先从已有插件中心安装。原生加密文件导入出口不依赖可选业务插件或 P2P 会话，仍遵循同一份延后恢复规则。

## 7. 职责与实现位置

- Rust：生成完整环境清单、归档加解密、持有合法文件句柄、预检 Provider、协调完整快照恢复、映射关系、保留待恢复包与导入日志。
- 业务插件：导出/验证/导入自身可移植记录，返回收据和 ID 映射；保持各自数据所有权。
- `studio.window-sync`：ICE 会话、STUN、DataChannel、背压、文件传输、接收回执、过期与取消。
- desktop-v2：沿用原生 UI 组件呈现选项、邀请/应答、进度和导入结果；不持久化密码、SDP 或业务包明文。
- 公共契约放 `packages/plugin-contracts`；主应用 CI 不依赖 Git 忽略的插件源码。

传输层首选 Node 内运行的 `werift`，通过独立适配器隔离其 API，使用 ICE 与可靠有序的 DataChannel。
理由是与现有独立 Node 插件及 JS 加密打包边界相符，避免为本轮增加原生 `.node` 二进制分发。
这是技术选型建议；实施首项须固定依赖版本，验证 Node 24 源码运行和现有 bundle 形式。失败则先报告实际阻碍，不偷换为 WebView 专用实现。
macOS/Windows 的发行包与异地网络连接必须分别验收，当前没有这些通过证据。

## 8. 连接与安全约束

- 使用 non-trickle ICE：本地候选收集完毕后一次导出邀请或应答，避免要求用户反复交换候选。
- 每个任务生成新的随机会话 ID、ICE 凭据和 DTLS 证书。应答绑定对应邀请摘要，错误会话或修改后的邀请拒绝使用。
- 邀请/应答只携带连接所需描述及版本，不携带包密码、业务资料或插件密钥。
- SDP 中的 DTLS 指纹必须与实际连接证书校验一致；应用核对码绑定有顺序的完整邀请、应答、会话和角色。
- 核对码采用 SHA-256 摘要前 96 bit，分为六组十六进制显示；两边都确认后才能发送文件。
- 邀请/应答过期时间建议为 15 分钟，连接时限 60 秒。已开始的传输另外限制空闲 60 秒、总时长 30 分钟。
- 首选公共 STUN 候选 `stun:stun.cloudflare.com:3478`，不请求 TURN 凭据。正式默认地址、服务适用政策、本机与双设备连通性及打包行为仍待验证；本文不把候选地址记为已通过实测。
- P2P 使用显式直连网络路径；这不是浏览器 Profile 代理或应用 HTTP 代理的失败回退。用户开始时说明网络元数据可见性。
- STUN 服务器地址只允许受校验的 STUN URI，不把邀请中的任意 URL、TURN 凭据或文件路径直接交给网络和文件 API。
- 不请求音视频设备权限。SDP、配对凭据和密码不写日志或 localStorage。

使用已存在的归档认证加密构件封装文件，迁移包密码与连接邀请分开传递。
DTLS 负责传输链路，归档加密负责临时文件与文件回退，不自行设计新的流密码。

## 9. 有界传输与状态

首版建议上限：最多 100 个 Profile、64 个插件，展开后配置/业务 JSON 总计 64 MiB，单个业务节 4 MiB。
这些是清单与 JSON 的预算，不限制浏览器快照为 64 MiB；站点数据库、扩展存储及业务附件按独立流式文件预算校验。完整快照沿用并核对现有归档的压缩载荷 20 GiB 及解包上限，逐项预估接收空间、解密空间和覆盖备份空间；超限明确阻止并建议分批，不静默裁剪站点资料。长耗时任务按有进度的字节传输显示，不因清单已到达就报告完成。
超过单行 RPC 预算的插件数据使用宿主发放的临时附件句柄，不把大块 JSON/base64 塞入 stdio。
邀请/应答输入各限制 64 KiB，ICE 候选最多 32 个；只接受当前版本和预期的一个数据通道。

文件按不超过 16 KiB 的 DataChannel 消息分片，另校验序号、总长度、文件 SHA-256 和结束消息。
发送端设置有限的待发队列，按通道缓冲与接收确认应用背压；接收端有总量、路径、文件类型和解压后总量限制。
接收方 fsync、原子落盘并验证完整文件后才返回收据。发送完最后一片不等于对方接收完成。
首版不承诺断点续传；重连创建新连接并从头重传冻结的同一归档。

会话状态区分：准备包、等待应答、连接中、等待双方确认、传输中、接收校验中、已接收、失败、已取消、已过期。
导入状态独立区分：等待预览、预检失败、等待确认、导入中、部分完成、等待安装插件、等待依赖、已完成、待核对。
插件停止、退出或取消时关闭 ICE/socket 和计时器，清理未完成的传输文件；清理失败有独立反馈，不删除已经接收完成的归档、待恢复包或用户资料。

## 10. 写入、幂等与失败恢复

所有选择先生成依赖闭包与冻结清单。目标端全部做只读预检后，划分依赖满足和待恢复的数据组，再按依赖顺序写入；缺失插件不绕过验证，也不阻塞无关数据组。
每个导入包和每项写操作使用稳定的操作 ID；Rust 日志保存任务状态、创建结果和插件收据。
Profile 创建超时先走现有操作核对，不发起新创建来绕过未知结果。
插件写入必须幂等；重试只处理未确认的项目，关系写入只引用已确认的目标 ID。
跨插件不宣称原子事务：失败时已创建的数据保留，界面列出成功和未完成项，用户可继续同一任务。
覆盖属于显式操作，要求目标未运行、身份和契约匹配，并先备份；首版默认只允许新增或明确跳过。

## 11. 验收与执行边界

实施验收应覆盖：邀请交换及跨会话拒绝、双方确认前零业务字节、真实 DataChannel 有界传输、损坏/截断/超额包拒绝、落盘回执、取消清理、插件退出与迟到结果隔离。
导入验收覆盖：Provider/Workspace 映射、完整站点资料的源端导出及目标端恢复、字段不支持、重复项、跨插件关系、创建结果未知、幂等重试、部分完成与重启恢复。Cookies、localStorage、IndexedDB、OPFS 和扩展等各数据类别分别验证；合成文件拷贝测试不能替代真实恢复。
缺失插件验收覆盖：B 仅安装传输插件、缺少被账号依赖的邮箱插件、缺少必需代理插件、插件版本/schema 不兼容、无有效授权、安装后重复点击继续、重启后继续、目标映射已失效、磁盘不足与显式放弃。验证加密资料不丢失、不自动安装、不自动恢复、不产生悬空关系，不在等待必需代理时回退直连。

可以直接执行源码 Vitest、无产物 TypeScript、lint、格式检查及受控 localhost 传输测试。
继续遵守不执行应用/插件 build、打包、Rust 编译/测试/Clippy 或图像验证的约定。
双设备公网打洞、真实厂商创建、Windows、签名和最终加密插件包运行在具备对应环境后验收，不虚构通过结果。

## 12. 用户已确认范围与本轮建议

用户已明确要求所有相关配置和持久浏览器资料，包括 Cookies、localStorage 等；本轮不再将只复制配置作为首版替代方案。业务资料允许复制，按用户选择纳入。

本轮建议将 B 缺少业务插件的处理定为第 6.3 节的加密保留、依赖分组与安装后显式继续恢复。相比全批阻断，这允许先获得已完整恢复的浏览器环境；相比静默跳过，保留了业务资料及之后恢复关联的机会。

业务资料首批建议以 Vinted 账号、邮箱、代理池和保存地址的完整关系链为基础，其他所选插件逐一接入版本化副本接口。尚不支持某插件的数据导出时，预览必须明确列为未覆盖；接收端缺失插件可以延后，不代表发送端根本没有导出的资料能事后补回。商品图片等所选记录必需的附件不能作为任意省略项。数据范围与各插件接入进度必须分别展示，不能把传输层通过描述为完整复制闭环已经完成。
