# Profile 插件列与插件面板

2026-11-19，依据本次对话确认的结构化 UI 方案实施第一条闭环。

## 职责

插件 manifest 声明 Profile 表格入口、名称、SVG 路径、能力和 viewId。
Rust 校验声明并通过目录返回，统一 UI 网关核对安装、授权、Profile UUID、连接和面板会话。
desktop-v2 提供一个插件列、一个与 Profile 详情共用位置的 PeekPanel 和通用 UI 渲染器。
插件返回分区、属性、表单、操作、确认和分页内容，插件负责数据、文案、状态与业务校验。

## 方案选择

本轮采用插件返回结构化界面，由宿主 ShardX UI Kit 渲染。
插件自带独立前端资源需要另外建设资源加载和消息桥接，留待实际组件需求推动。
宿主新增通用协议组件时需要发布应用，已支持组件的内容与业务流程随插件更新。

## 本轮范围

- 可选 manifest ui 声明、SDK 严格 schema、Rust 校验和目录透传。
- 通用 Profile 面板会话及 open/dispatch/close 网关，支持上下文和插件安装修订核对。
- 共用插件列、图标、420px / 360px 面板和结构化内容渲染。
- Profile Peek 标题栏复用相同插件图标，插件面板提供返回 Profile 详情的入口。
- 分区操作可声明 header/body 位置，视图级操作固定底栏，内容区域独立滚动。
- Vinted 插件提供未绑定、账号选择、新建并绑定、详情、编辑、确认解绑、短信读取及衣柜分页。
- 创建关联在插件存储的一次 mutate 中提交，修改与解绑在插件事务内检查预期修订。
- UI 数据仅在会话内存中保存，列表入口不读取账号账密，关闭和切换使旧响应失效。

## 验收

新增任意受控插件只修改其 manifest 与插件 UI 方法即可在共享列展示入口并打开内容。
Vinted 业务字段与流程位于 plugins/vinted-accounts，宿主新增代码使用通用协议。
测试覆盖声明拒绝、插件隔离、绑定修订、原子创建、会话切换和迟到响应。
本地执行直接测试、lint、无产物 TypeScript、rustfmt。应用构建和 Rust 编译由 CI 完成。
