# ecom agent 完整能力与体验补齐

用户已确认实施审计中的全部未完成项、优化项和增强建议。
沿用既有 Rust + LangGraph.js + Playwright，不增加运行服务或另一个数据库所有者。
当前共享功能分支中的商品、Agent、工作流和用户修改全部保留。

## 实施选择

采用现有协调器内扩展：Rust 持久化调度、控制、草稿、用量和通知收据；
销售插件负责平台读回、模型调用和受限工作流；React 使用紧凑 shadcn 页面。
独立任务服务增加部署成本，浏览器页面定时器不能保证退出后恢复，因此不采用。
本设计落实用户刚确认的完整清单，不再增加审批或原型阶段。

## 完整范围

1. 结果页丢失时，有限读取本人最近刊登并验证唯一候选；未知提交不能重发。
2. 读取和模型失败保留重试次数、截止时间与冷却；外部写入不得自动重放。
3. 提供方并发上限、同账号冷却和独立模型槽位/速率队列。
   上游没有可靠容量接口时使用用户设置的上限，不伪造许可证容量。
4. 批次和单窗口暂停、恢复、取消、人工接管；隔离完成后才提示可人工操作。
5. 单商品跳过与未提交资料调整；已提交/结果未知的商品只能核对。
6. 商品级进度、首图、业务化阶段、错误原因及针对性恢复操作。
7. 真正带图片的视觉测试、判断测试与英文文案测试；分别展示结果。
8. 集中运行前检查；区分已验证资料与启动后才能核对的登录状态。
9. SQLite 草稿和模板；只存稳定关系和编辑值，载入时重新取得商品/窗口。
10. 待处理工作台，展示原文、候选文案、判断原因，允许修订/跳过/继续。
11. 商品、窗口、账号及执行历史相互跳转；不能把分配当成发布成功。
12. Bark 批次结束和需要处理通知，稳定通知 ID、有限失败重试，普通步骤不通知。
13. 模型请求次数、耗时、可取得的 token 用量、配置价格后的估算费用；
    批次请求/费用预算，明确未知用量和已消费费用不可撤回。
14. 可配置已结束任务保留策略与显式清理，保护未知动作、待同步、资源占用和商品发布事实。

## 公开接口

既有 `sales_agent_batch_*` 保留，批次控制增加 `takeover`。
新增命令使用单一当前格式：

- `sales_agent_preflight({ input })`
- `sales_agent_job_control({ id, action })`
- `sales_agent_items({ id, page, pageSize, attentionOnly? })`，`id` 为作业 UUID。
- `sales_agent_item_control({ jobId, productId, action, override? })`
- `sales_agent_artifact_preview({ jobId, artifactId })`
- `sales_agent_workspace_list/get/save/delete`：草稿/模板，修订冲突必须反馈。
- `sales_agent_usage({ id })`：批次聚合用量，明细使用独立分页接口。
- `sales_agent_model_requests({ id, page, pageSize })`：逐次请求的独立分页查询；
  不返回端点、密钥、scope 或请求体。
- `sales_agent_retention_preview` / `sales_agent_retention_clean`：预览后明确清理。

反向宿主增加 `agent.controls.get`、`agent.model.acquire`、`agent.model.complete`。
模型许可使用稳定 requestId、scope 和 fence，完成收据幂等；只允许冻结的模型端点。
控制指令持久化并按 revision 消费；不能修改既有提交意图或清空动作日志。
插件增加 `salesAgent.notifications.send`，只由 Rust 内部协调调用。
SDK 是公开字段来源，Rust 手写 DTO 必须同步验证，不能称作生成绑定。

## 默认与边界

窗口并发沿用 3；独立模型并发默认 3。
读取最多重试 2 次，基准等待 2 秒，平台限流冷却默认 30 秒；设置有严格上下限。
价格默认未知，预算未设置时不阻断；设置费用预算必须有完整模型价格配置。
Bark 默认关闭；只有用户保存通知配置才发送。测试只使用受控服务。
草稿和模板由 Rust 明文写 SQLite；不写 localStorage/Keychain。
历史自动清理默认关闭，显式清理必须先预览；未知或待同步任务不可清理。
已确认封禁停止全部写任务，人工操作入口不能绕过封禁或未知提交防重。
分类继续选填；所有自动文案仍为英文，模型不得捏造商品事实。
保持现有 460px 内滚动分配面板，不用新增大卡片挤占表格。

## 验证

直接 Vitest、无产物 TypeScript、ESLint、Prettier、rustfmt 和受控 Chromium。
关键用例涵盖重启、迟到回执、配额竞争、退避取消、结果候选不唯一、
人工接管在途动作、草稿关系过期、未知结果禁止跳过/修订、通知去重与清理保护。
不执行本地构建、打包、Rust 编译/测试/Clippy，不进行真实上架/发信。
原生与真实厂商验收由 CI 和受控设备补充，不能将源码与 mock 结果写成已验收。
