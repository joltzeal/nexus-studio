# 商品插件实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 提供独立持久化的商品插件，支持手动创建、资料导入和 AI 生图商品导入，作为后续 Agent 的商品来源。

**Architecture:** `studio.products` 声明 `product.catalog` 能力，Node 插件独立保存商品文档与图片副本；Rust 继续只负责宿主与能力检查。桌面页面通过公开契约和现有插件 IPC 调用。生图导入由页面协调读取、分块复制和幂等提交，商品不引用 AI 插件的私有文件路径。

**Tech Stack:** 固定 Node 24、TypeScript、Zod、现有插件行协议、React 与 shadcn。

**Spec:** 本轮用户要求：先做商品插件；分类非必填；后续 Agent 从商品插件读取，商品与窗口采用固定高度的左右拖拽关系面板。

## Global Constraints

- 保留上轮未提交的 Agent 原型；本轮不实现真实 Agent，不更改浏览器自动化。
- 不执行本地构建、打包、Rust 编译/测试/Clippy，不创建提交或发布。
- 不新增数据库所有者；插件按现有模式使用独立明文 JSON 与图片目录。
- 分类允许为空；手动资料与实际平台执行分开，不增加虚假的发布成功状态。
- 图片必须归商品插件所有，不能依赖 AI 生图历史的保留期限。

## Review Focus

- 重复导入生图记录不新增重复商品，也不覆盖手工编辑。
- 删除 AI 生成记录后，已导入的商品图片仍可读取。
- 文件写入失败、损坏文档和并发旧版本编辑不能反馈保存成功。
- 导入内容超限、无效图片、乱序分块和中途取消必须明确失败。
- 大量商品使用后端分页和局部滚动；插件不可用时不显示可保存的假表单。
